# 004：給人玩的預設 CPU 速度

狀態：**READY**
日期：2026-09-17
對應：issue #9（節拍）；依據 `docs/re/010`；dosgolem 規格 `198`（DOSBox 相容 cycles）

## 1. 決定

**預設 750 cycles（DOSBox-X「286 8 MHz」），另提供 240 cycles（「8088 XT 4.77 MHz」）選項。**
前端以 dosgolem `SetDOSBoxCycles` 設定速度，並以牆上時間對齊（每秒執行 `cycles × 1000` 個 cycle）。

## 2. 理由

1. **說明書列的兩種機型都成立**：硬體配備寫 IBM PC XT／AT 或相容機型。兩個選項各對應其中一種，不另外發明速度。
2. **難度不隨速度改變**：戰鬥敵我雙方的進度都綁在 CPU 上（`docs/re/010` §3、§4.2）。
   同一份輸入在 240 與 750 cycles 下，12 組裡 8 組玩家損血完全相同；分岔的 4 組中 XT 損血較少 3 組、較多 1 組，樣本太少，看不出慢機比較難或比較容易。
   所以選速度只是選節奏，不是選難度。
3. **節奏**（dosgolem 量測，`docs/re/010`）：

   | 項目 | cycles | 240（XT） | 750（AT） |
   |---|---:|---:|---:|
   | 第一場戰鬥（按住攻擊到敵人倒下，12 種按住起點） | 880 萬–1,840 萬 | 51–77 秒 | 12–24 秒 |
   | 迷宮前進一步（畫面畫完） | ≤ 20 萬 | ≤ 0.83 秒 | ≤ 0.27 秒 |

   XT 下每場戰鬥要持續按住空白鍵將近一分鐘；AT 同樣在說明書範圍內，戰鬥時間約為 XT 的 1/3。
4. **參照可重現**：兩個值都是 DOSBox-X 選單的機型預設，玩家用 DOSBox-X 對照時設得出一樣的值；
   兩種速度下 dosgolem 與 DOSBox-X 的戰鬥時間差 ≤ 5%（`docs/re/010` §1）。

## 3. 不選的值

| 值 | 不選的原因 |
|---|---|
| dosgolem 預設（指令數時鐘，約每秒 1,158 萬道） | 戰鬥約 1 秒結束，人來不及反應 |
| 1,510 cycles（286 12 MHz） | 說明書沒列；AT 原機是 6／8 MHz。可以當進階選項，不當預設 |
| 週期時鐘 `-cpuhz` | 週期表以 386 為準，無法對應 DOSBox cycles（規格 `198` §1） |

## 4. 驗收（M2 前端）

1. 前端未指定速度時，機器的 `DOSBoxCycles()` ＝ 750。
2. 選項 `xt` 時 ＝ 240；兩者切換後 IRQ0 間隔依規格 `198` §4 第 2 項重算。
3. 牆上時間對齊：以 750 cycles 跑第一場戰鬥（`tools/battle-pace.sh at8` 的輸入），牆上時間與換算秒數差 ≤ 10%。
4. 反向對照：不設速度時第 1 項失敗。

## 5. 重開條件

- 發現遊戲中有綁計時器、在慢機上明顯較難（或較易）的段落。
- 玩家回饋 AT 節奏太快（例如迷宮中的即時事件來不及反應）。
