# 001：PC 喇叭配樂的比對方法

狀態：**READY**
日期：2026-09-17
對應：issue #6；格式依據 `docs/re/006`

## 1. 目的

驗證 dosgolem 合成的 PC 喇叭配樂（`-dump-tone-wav`，dosgolem `docs/spec/195`）與 DOSBox-X 錄音的**音高與節奏**一致。
不比波形：兩邊的方波相位、濾波、音量都不同，逐取樣比對沒有意義。

## 2. 兩層驗證

| 層 | 比什麼 | 參照 | 判準 |
|---|---|---|---|
| A. 事件層 | dosgolem 寫到埠 `42h`／`61h` 的音符事件 | `.IBM` 檔的記錄（`docs/re/006`） | 頻率、刻數**逐筆完全相同** |
| B. 聲音層 | dosgolem WAV 與 DOSBox-X WAV 分析出的音符段 | 彼此 | §4 |

A 證明「原版驅動在 dosgolem 上照資料播」，B 證明「合成出來的聲音與另一個實作聽起來一樣」。只做 B 的話，
兩邊同錯（例如都漏播一段）也會通過。

## 3. 分析器（兩邊用同一支）

`tools/music_compare.py`：

1. 讀 WAV（PCM 8 位元無號或 16 位元有號，多聲道取平均），去掉直流。
2. **上升過零點**：以全檔峰值的 10% 做遲滯（先低於 −h 再高於 ＋h 才算一次），過零時間以線性內插到小數取樣。
3. **切段**：相鄰過零間隔即週期。下一個週期與本段目前週期中位數相差**超過 4% 與 1.5 個取樣兩者中較大的那個**，或間隔 **> 40 ms**（最低音 93 Hz 的週期約 10.8 ms），就開新段。
   1.5 個取樣的下限是為了硬邊方波：過零點只能落在取樣格上，22,050 Hz 下 988 Hz 一週期約 22.3 個取樣，週期會在 22／23 之間跳（差 4.5%），只用 4% 會把一個長音切成許多碎段。
4. 一段：起點 ＝ 第一個過零點，終點 ＝ 最後一個過零點加一個週期，頻率 ＝ 週期數 ÷ 時間跨度。少於 3 個週期的段丟掉。

同頻率、中間沒有休止的相鄰音符會合併成一段——兩邊都會合併，不影響比對。

## 4. 比對與判準

1. 對齊起點：DOSBox-X 錄音開始的時間是任意的，常漏掉開頭幾個音，所以**不假設第一段對第一段**。候選位移取兩邊前 10 段裡頻率相同（≤ 2%）的配對，挑讓前 50 段配對最多的位移；只比兩邊都有錄到的時間範圍。
2. 逐段配對：dosgolem 每一段在 DOSBox-X 裡**依起點時間**找起點相差 ≤ 50 ms、頻率相差 ≤ 2%、尚未被配對的段。
   不以索引往後看固定段數：中間缺一整塊時，索引式配對會卡住，之後正常的段也全部連鎖失敗，看不出缺在哪裡。
3. 對配對成功的段做「DOSBox-X 起點 對 dosgolem 起點」的線性回歸。

| 指標 | 通過 |
|---|---|
| 配對成功率：在兩邊都有錄到的時間範圍內，**分別**以 dosgolem 段數與 DOSBox-X 段數為分母，兩個都要達標 | ≥ 98% |
| 頻率誤差（配對段） | 全部 ≤ 2% |
| 速度：回歸斜率 | 與 1 相差 ≤ 0.5% |
| 起點殘差（回歸後）第 95 百分位 | ≤ 20 ms（約 1.5 刻） |

1 刻 ＝ 16571 ÷ 1193182 秒 ≈ 13.9 ms。DOSBox-X 以牆上時間混音，有數 ms 的緩衝抖動，所以門檻給到一刻半。

## 5. 輸出

JSON：兩邊段數、配對數、兩個方向的成功率、頻率誤差最大值、斜率、殘差分位數、兩邊各自未配對段的前 20 筆（時間、頻率）。
只用單一方向當分母會漏掉一種錯：dosgolem 漏播一段時，它的段數跟著變少，以它為分母的成功率仍是 100%。
不通過時要能看出是**音高錯、速度錯，還是缺段**。

## 6. 不做

- AdLib（`.MID`）路徑：issue #5。
- 音量、音色、濾波。
