## 1. 目標

**基於原版重新繪製**畫面元素，畫在放大後的畫布上。**原版畫面永遠是預設**。
重繪不是放大：外框、位置與顏色照原版，形狀重畫。

第一版範圍：`SCREEN.PBL` 五張 ＋ `MENU.PBL` 一張，
也就是整個畫面背景與指令面板（`docs/re/038` §3）。
怪物、房間、迷宮視野不在第一版。

## 2. 主題是資料

```
theme/
  hd/
    manifest.json
    SCREEN-00.png   960×120（3 倍）
    SCREEN-01.png
    ...
```

`manifest.json`：

```json
{
  "name": "hd",
  "title": "高解析度",
  "scale": 3,
  "entries": [
    {
      "pbl": "SCREEN.PBL",
      "image": 0,
      "at": [0, 0],
      "png": "SCREEN-00.png",
      "scaler": "hq3x",
      "match": [0, 0, 320, 40]
    }
  ]
}
```

| 欄位 | 意義 |
|---|---|
| `pbl`／`image` | 來源是哪個檔的第幾張（溯源用，執行期不讀原版檔） |
| `src` | 來源圖裡的子矩形 `[x, y, w, h]`，省略 ＝ 整張（見下） |
| `at` | 畫在原版座標的哪裡（`docs/re/038` §3 的量測值） |
| `png` | HD 圖，尺寸必須是 `(w×scale, h×scale)` |
| `kind` | `redraw`（新畫，可散布）或 `original`（沿用原版，不可散布） |
| `scaler` | `kind` 為 `original` 時用哪種放大（`nearest`／`hq3x`） |
| `match` | `Watcher` 要比對的原版區塊（原版座標）。省略時 ＝ 整張 |

**`src` 是必要的，不是方便**：實測（`docs/re/038` §10）顯示同一張圖裡面就有兩種素材，
`SCREEN.PBL` #0 同時有標題字（放大器會把方角磨圓，要 nearest）與人物和機械（hq3x 明顯變好）。
一張圖一個放大器的假設不成立。

**`match` 與 `at` 分開是必要的**：狀態列那兩條有 18% 會被原版蓋掉
（`docs/re/038` §3），整塊比對永遠不會成立。

## 3. 重繪管線

**使用者定案 2026-09-30：基於原版重新繪製，不是放大。**
放大的實測結果（`docs/re/038` §10）留作對照，不是交付路線。

### 3.1 幾何元素：抽結構再向量重畫

1. `tools/hd/elements.py`：解 `.PBL` → 逐色號連通塊 → 列出元素（色號、外框、像素數）。
2. 人判斷每個元素是什麼基元（箭頭、框線、鍵帽、格線、儀表、管線）。
3. 基元寫進 `theme/hd/draw/<檔>-<圖號>.json`，用原版座標描述。
4. `tools/hd/render.py`：讀基元 → 以 `scale` 倍算出像素 → 抗鋸齒畫出 PNG。

**重畫的約束是外框、位置與顏色照原版**，形狀可以畫得比原版好
（原版的箭頭頭與柄隔著 3 px，向量化之後要接起來才讀得成箭頭，`docs/re/038` §11.4）。

⚠ 座標一律量**已解出來的 PNG**。`tools/pbl.py dump` 的 `.idx` 前面有 4 bytes 檔頭，
直接當像素陣列讀會整體左偏 4 px 而且不報錯（`docs/re/038` §11.3）。

### 3.2 細密美術：要真的重畫

`SCREEN.PBL` 的 1,000 個 8×8 格裡有 355 格是 5 色以上的細密美術
（人物插圖、機械帶、標題字），而且分佈平均，沒有乾淨的切法（`docs/re/038` §11.1）。

**這一段沒有可以自動擬合的基元，是美術工作，不是工具問題。**
在它有人畫之前，`entries` 裡對應的子矩形沿用原版（`scaler: "nearest"`），
畫面上會是「重繪的結構 ＋ 原版的美術」。這是可接受的中間狀態，不是缺陷。

### 3.3 授權

重繪的結構元素是新作品，**可以進 repo 與發行包**。
沿用原版的子矩形仍然是原版素材，受 `AGENTS.md` 的 `[HARD]` 管，不得散布——
所以發行包裡那些格子是空的，由玩家自備的原版填。

## 4. 執行期

- `-theme <名>` 選主題，預設空（原版畫面）。
- `Shift+F5` 在原版與目前主題之間切換（F5 是中英切換，同一類的顯示開關）。
- 載入時逐筆登記 `xlate.Watcher`，`Make()` 回傳 `Art` 疊字（每列一筆，dosgolem `204` §2.4）。
- `manifest` 的 `scale` 與 `-scale` 不符時**整個主題不載入**，開場提示一次。
- `png` 缺檔或尺寸不符 → **啟動就報錯結束**，不靜默略過
  （比照字型缺字的規則：`AGENTS.md`「沒有翻譯的字串要看得出來」）。

## 5. 與中文疊字的關係

圖與字在同一層的**不同組**（dosgolem `204` §2.1）：圖先畫、字後畫，
重疊移除只在同組內發生。面板上的中文不受 HD 圖影響，反之亦然。

原版在 HD 圖上面畫東西時，**那幾格自動破洞露出原版**（`204` §2.2 的逐格失效）。
迷宮視野、訊息框、狀態數值、走路中的角色都靠這個機制正常顯示。

## 6. 驗收

1. **反向對照**：`-theme` 為空時，四個檢查點畫面與今天逐像素相同（差 0）。
2. **遊戲狀態不變**：同一段重播開主題與不開，結束時指令數相同、存檔逐位元組相同。
3. **破洞落在該破的地方**：迷宮畫面上，HD 疊字失效的格子集合
   ＝ 原版把 `SCREEN.PBL` 蓋掉的格子集合（拿 `docs/re/038` §3 的差異圖當預期值）。
   多破或少破都不算過。
4. **缺圖報錯**：把一個 `png` 改名，啟動要以非 0 結束並指出是哪一筆。
5. **倍率**：`-scale 2` 配 `scale: 3` 的主題 → 不載入、有提示、畫面是原版。
6. **成本**：開主題與不開，`Frame` 的耗時與每秒幀數各量一次（不設門檻，要有數字）。

## 7. 授權

重繪改變了這一條。**新畫的結構元素是新作品，可以進 repo 與發行包**，
不受 `AGENTS.md` 的 `[HARD]`「不得散布原版素材」限制。

還沒重畫、沿用原版的子矩形仍然是原版素材，不得散布。
發行包裡那些格子留空，執行時由玩家自備的原版填上去。

⚠ `manifest` 要標出每一筆是「重繪」還是「沿用原版」，打包時據此決定帶不帶那個檔。

## 8. 不做

- 換配色（改色盤是另一件事，成本與風險都不同）。
- 主題編輯器。
- 執行期縮放（`Pix` 是烘好的，dosgolem `204` §2.3）。
- 怪物、房間、迷宮視野（第二版，要先補 `sub_18A98` 的攔截，`docs/re/038` §6）。
