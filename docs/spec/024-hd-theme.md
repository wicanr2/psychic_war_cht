### 1.2 ALLY #0 的最小接入契約（READY）

本批只支援研究 §22 的已證實位置：`ALLY.PBL` #0，原版 24×32，位於 `(264,152)`，
倍率 3 的 PNG 為 72×96。來源 SHA-256 為
`c88ad34c06d3c5ab68ff2b4aafe2a0fde51b513c375c1d90924563f1b1557219`，
實際 31 張；載入核對來源、數量與 #0 尺寸。後續位置及#1擴充見§1.15／§1.16／§1.17，其他圖號、位置、裁切及鏡像拒絕載入。
既有候選只用來驗接入，造型／比例仍待美術驗收，不因 PNG 解碼通過而升格為完成。

- 沿用 schema 1，在背景項目之後加入 `pbl:"ALLY.PBL", image:0, at:[264,152]`；
  不改存檔、原版色號緩衝或遊戲記憶體。`src` 只接受省略或完整 `[0,0,24,32]`，
  `match` 只接受省略或原版背景 `[0,0,320,40]`；後續明示左側錨點擴充見§1.10。
- 每列的不可變 Reference 來自解碼後的 ALLY #0，不使用 SCREEN 黑底或當前被遮畫面。
  每個原點對齊的 8×8 格完整比較；任一原版像素改變，只遮該格，恢復後重顯。
  完全沒有非零色號的原版格保持透明，避免人物消失後黑底吻合留下 HD 殘片。
- 圖面出現條件與遮格分開：完整 24×32 原版圖吻合可確認已在畫面上，支援載入既有 state；
  穩定背景失配則撤銷出現狀態。出現後局部遮擋不撤銷整張圖。
- `Theme.Attach(o)` 只讀觀察已證實的貼圖入口 `0161:8705`。`OnCall` 追加觀察者，
  不取代既有掛鉤；同一主題只能接上一個 Oracle，重複接同一個不重複登記。
  AX 低位元組 0、CX 的兩位元組各乘 4、DX 的兩位元組各乘 8，且正好為本批原座標／尺寸時，
  比較 DS:BX 的 384 bytes 原始 4bpp 與 ALLY #0 的獨立解碼打包結果，吻合才確認來源。
  覆蓋整個角色矩形的其他貼圖先撤銷本批來源；不把未知 AL 模式或 XOR 差分解釋成完整圖。
  其後只有完整原版像素吻合或已證實來源事件能重新啟用。
- 兩個前端均在推進原版之前 Attach；HD 停用時仍觀察生命週期，重新啟用不沿用過期來源。
  成功讀檔清除圖面及出現狀態，原有掛鉤保留；下一幀從完整原版圖重新辨識。
- 驗收須有正常名字輸入路徑，兩側在執行前固定 state 中的 86AFh，保持等價輸入；
  比較完整記憶體、暫存器、步數、cycles 與原版畫面。另驗局部遮格／恢復、清除、
  未支援的替換圖、載回 state、重複 Attach 及區外像素負對照。

入口：`apps/psychicwar/theme/`；研究及驗收掛在 `docs/re/038` §34。
本契約只閉合 #0 的技術接入，其他 30 張與敵人／效果維持 §1.1 的必要工作。

### 1.3 ENEMY00 #3–#5 的動作接入契約（READY）

來源與差分證據為研究 §20：`ENEMY00.PBL` SHA-256
`8241b0ea73b1e7402b13adc434f10a5b1288f88f01fcfc3ba5710e4923fe6067`，

  載入拒絕相同來源重複或同位置完全相同 Reference 的歧義清單。
  已啟用的圖在局部遮擋時保留逐格可見性，不把上一個動作的共用格疊到新動作上。

- AL=01 僅接受研究 §20 已證實的兩個轉換：#3→#4、#4→#5。
  進入前原版矩形須完整吻合前一張，DS:BX 的 384 bytes 須等於兩張完整圖獨立解碼的打包 XOR；

  原版仍自行完成貼圖；覆繪層只讀辨識，不執行 XOR、不寫原版 RAM／畫面。

  進入後第一指令仍是 #3，之後逐步變更 1／14／40／60／80／88 像素，矩形外均不變。
  在入口確認新來源後，直到已證實返回點 `0161:8751`，保持本次來源認定並逐格比對目標 Reference；
  期間禁止完整舊畫面重新啟用舊動作。未知來源在此期間保持原版；返回後恢復全圖辨識。
  讀檔、畫面尺寸／錨點失配須清除閘門。來源讀取限制在 A0000h 以下的 RAM，
  不透過 VGA 匯流排讀取改變其鎖存器；越界來源視為未知，不寫原版。
- HD 開關、讀檔及語言契約沿用 §1.2／§4.1。成功載回 state 後由完整原圖恢復目前動作，
  不序列化顯示資產、來源認定或動作索引；未選主題維持原版預設。
- 正常路徑可先從 §1.2 的固定 `06-name.state` 輸入名字，以便涵蓋早已印出的方位中文；
  接續到固定 `07-first-play.state`（SHA-256
  `56c489deaa57cd26fbd4f39f374e87db2f51e7d1275c440c9805321fb09bd532`）開始，
  新正常名字終點在第 42,000,001 步的完整記憶體、暫存器、畫面及 cycles，
  與該存檔推進一指令完全相同，見研究 §35。執行前唯讀核對種子 86AFh，
  使用研究 §20 十一鍵序列在驗證終點前已達時間的前進按下／放開前綴，兩側不重擲。
  核對三次來源／原版前後圖、逐格完整期望、角色區外差、動作負對照、整份狀態、
  HD 切換與實際 state 載回，以及 ALLY #0 舊契約回歸。

| 欄位 | 意義 |
|---|---|

**`src` 是必要的，不是方便**：實測（`docs/re/038` §10）顯示同一張圖裡面就有兩種素材，
`SCREEN.PBL` #0 同時有標題字（放大器會把方角磨圓，要 nearest）與人物和機械（hq3x 明顯變好）。
一張圖一個放大器的假設不成立。

**`match` 與 `at` 分開是必要的**：狀態列那兩條有 18% 會被原版蓋掉
（`docs/re/038` §3），整塊比對永遠不會成立。

## 3. 重繪管線

**使用者定案 2026-09-30：基於原版重新繪製，不是放大。**
放大的實測結果（`docs/re/038` §10）留作對照，不是交付路線。

### 3.1 幾何元素

**只重畫有斜邊或曲線的元素。** 軸對齊的直線用 nearest 放大是完美的，
重畫它們在畫面上等於沒做——`docs/re/038` §12.1 的量測：≤2 色的格子只有 7.1% 有鋸齒，
3–4 色 39.1%，≥5 色 54.6%。原版的 UI 框架幾乎全是軸對齊直線，
所以這一條天生就小，不是做不完。

兩支工具：

| 工具 | 做什麼 |
|---|---|
| `tools/hd/render.py` | 基元 JSON → 任意倍率的 RGBA PNG。座標用**原版像素**（可小數）、顏色用 **EGA 色號**，所以配色自動跟原版一致，「風格跟原版相近」由格式本身保證。4×4 超取樣抗鋸齒。基元 `poly`／`rect`／`grid` |
| `tools/hd/dedither.py` | 兩色棋盤格 → 真正的中間色。判準是四鄰中有 N 個同色、且自己與四鄰皆不同色（預設 N=3；N=4 會在抖色區邊緣留一圈沒解到的格子）。輸出 RGBA，非抖色一律透明讓原版透出來 |

基元資料放 `theme/hd/draw/<檔>-<圖號>.json`。

**重畫的約束是外框、位置與顏色照原版**，形狀可以畫得比原版好
（原版的箭頭頭與柄隔著 3 px，向量化之後要接起來才讀得成箭頭，`docs/re/038` §11.4）。

⚠ 座標一律量**已解出來的 PNG**。`tools/pbl.py dump` 的 `.idx` 前面有 4 bytes 檔頭，
直接當像素陣列讀會整體左偏 4 px 而且不報錯（`docs/re/038` §11.3）。

### 3.2 細密美術：交給畫圖代理

使用者定案 2026-09-30：**細密美術用 codex 給提示詞繪製**。
規格與提示詞在 `tools/hd-art-instructions.md`（比照 `tools/baked-authoring-instructions.md`
與 `tools/playtest-instructions.md` 的做法）。

三塊素材：人物 `girl`（264×456）、機械帶 `mech-mid`（360×192）、
底部機械帶 `mech-bot`（960×48）。參照圖在 `workplace/hd/art-ref/`，
交回來放 `workplace/hd/art-in/`。

**標題 Logo 不重畫**：`docs/spec/011` §6 已經定案標題美術字沿用原版，
`SCREEN.PBL` 上的是同一個字標，照同一個決定辦。

### 3.3 整屏外框也交給畫圖代理

使用者定案 2026-09-30：**外框也重新繪製**。

§12.1 的量測說「軸對齊直線 nearest 放大是完美的」，講的是**鋸齒**。
外框重畫要的不是消鋸齒，是**重新設計視覺處理**——1987 年的單像素框線就算放大得再乾淨，
仍然是 1987 年的框線。這兩件事不衝突，量測也不構成反對理由。

一張 `chrome.png`（960×600）涵蓋整個畫面框架，包含 §3.2 的機械帶。

**正確性由 `tools/hd/mask.py` 保證，不靠代理自律**：原版背景是黑色的像素
（佔 60.4%），遊戲會在上面畫迷宮視野、訊息、狀態數值與角色。
這支工具把那些像素一律改成全透明，所以代理畫錯也不會佔住遊戲的畫面。

代理自己要顧的是**對位**：指令面板、訊息框、狀態列內部、迷宮視野四個矩形的邊界
必須落在跟原版相同的像素行列。框線一偏，遊戲畫上去的字就會壓在框上。
這一項遮罩救不了，要代理自己比對。

右側人物不在 `chrome` 裡，由 `girl.png` 另外疊。

### 3.4 為什麼要分兩條路

`SCREEN.PBL` 的 1,000 個 8×8 格裡有 355 格是 5 色以上的細密美術
（人物插圖、機械帶、標題字），而且分佈平均，沒有乾淨的切法（`docs/re/038` §11.1）。

**這一段沒有可以自動擬合的基元**，所以幾何走程式、美術走畫圖代理。
在它有人畫之前，`entries` 裡對應的子矩形沿用原版（`scaler: "nearest"`），
畫面上會是「重繪的結構 ＋ 原版的美術」。這是可接受的中間狀態，不是缺陷。

### 3.5 授權

重繪的結構元素是新作品，**可以進 repo 與發行包**。
沿用原版的子矩形仍然是原版素材，受 `AGENTS.md` 的 `[HARD]` 管，不得散布——
所以發行包裡那些格子是空的，由玩家自備的原版填。

### 3.6 原版排版與前後關係（使用者定案 2026-10-01）

- **人物與框線的位置、範圍、功能區邊界沿用原版**；不可為避框線而縮小或平移人物。
- 人物來源矩形仍是 `(232,0,88,152)`；可見裝飾區到 `y=143`，`y≥144` 留給原版遊戲。
  3 倍畫布放在 `(696,0)`，保留 264 像素寬；裁掉越界部分，不使用舊版的 250 像素等比縮圖。
- 靜態合成順序：**原版底圖 → 美女圖 → 前方框架／框線／控制元件**。
  人物下緣應被原版位置的控制台自然遮住，頂部框架也在人物前方。
- 遊戲畫面的合成順序：上述背景先經 **8×8 原版格遮罩**，保留原版動態內容，
  再畫中文。中文、訊息、數值、按鈕及視野的位置不因 HD 主題移動。
- 前後圖層可先合成一份背景資產，再交給 204；不得靠不穩定的 watcher 新增順序決定前後。
- 原型入口 `tools/hd/preview_layout.py` 與原版框架分區、限制見研究 §31。
  原型部分框架沿用原版像素，不能當作完整手繪框架或正式執行期完成。

## 4. 執行期

- `-theme <名>` 選主題，預設空（原版畫面）。
- `Shift+F5` 在原版與目前主題之間切換（F5 是中英切換，同一類的顯示開關）。
- 載入時登記 `xlate.Watcher{Art:true, ArtKeys:全部列的 Key}`，`Make()` 回傳每列的圖面。
  依 204 提供明確 `Reference`／`PixScale`／`Order`，不能從當前被遮的畫面採樣基準。
- `manifest` 的 `scale` 與 `-scale` 不符時**整個主題不載入**，開場提示一次。
- `png` 缺檔或尺寸不符 → **啟動就報錯結束**，不靜默略過
  （比照字型缺字的規則：`AGENTS.md`「沒有翻譯的字串要看得出來」）。

### 4.1 第一批載入與生命週期契約

本節是遊戲專屬接合契約；不改原版程式、存檔或規則。原版證據等級及輸入 SHA-256
沿用研究 §29／§31／§32：SCREEN 五條在 `(0,40n)`，MENU #0 在 `(160,4)`，
組合背景為 320×200；這些位置與尺寸已證實。美女／框架分區仍為 §31 的強證據。

- `-theme` 可為 `theme/<名>` 下的名稱或明確目錄路徑；資料根沿用
  `apps/psychicwar/paths.go` 的執行檔旁／macOS Resources／工作目錄搜尋方式。
  空值不讀主題或 PBL，不登記 watcher，維持原有畫面。
  逐步工具沿用其 `-text` 的工作目錄習慣，以工作目錄的 `theme/<名>` 或明確路徑載入；
  載入器在 `apps/psychicwar/theme/`，不引用 Ebiten，維持無顯示伺服器可執行。
- 清單必須為 `psychic-war-theme/1`，名稱非空、正倍率、至少一筆；未知欄位及額外 JSON
  拒絕載入。每筆有 `pbl`、`image`、`at`、`png`、`kind`；`src` 省略為整張。
  `kind` 僅接受 `redraw`／`original`；`scaler` 是製作紀錄，不在執行期縮放。
- SCREEN 必須實際有五張 320×40，MENU 必須實際有一張 88×72；核對研究 §29
  記錄的兩檔 SHA-256，任何不符報錯。依 SCREEN 五條後 MENU 的順序重建不可變色號背景。
  不從當前遊戲畫面取樣 Reference，不把被角色覆蓋的背景當作基準。
- `src` 必須在來源圖內；`at` 必須等於該圖原版位置加 `src` 的偏移，PNG 尺寸必須為
  `src` 寬高乘清單倍率。PNG 路徑限制在主題目錄內，拒絕絕對路徑、父目錄及符號連結越界。
  PNG 先驗尺寸再解碼，轉為非預乘 RGBA；缺檔、錯尺寸及來源錯誤均帶筆號報錯。
- 每筆繪製矩形向外補齊到原點 `(0,0)` 的 8×8 網格，補出的 PNG 像素透明；
  Reference 使用組合背景，包括補出的區域。MENU 的 y=4 不另起一套格線。
  每個 8 像素高的列有唯一 Key，全部列登記同一 Art watcher；不同筆依清單順序繪製。
  重繪 PNG 已按 §3.6 合成人物在後、框線在前，不靠 watcher 註冊順序拆分人物與框線。
- `match` 若明示，須為畫面內正矩形；Want 從組合背景擷取。每幀先驗錨點，
  再驗每一繪製格；錨點消失即整筆不畫，再出現即恢復。
- 清單倍率與前端倍率不同：只讀並驗清單，記一次提示，整個主題停用；
  不讀 PNG、不縮放、不因不存在的 PNG 報錯。中文是否可用沿用既有三倍字型規則。
- HD 啟用與英文模式是兩個獨立狀態。Shift+F5 只切 HD，F5 只切中英文；
  沒有主題時 Shift+F5 不影響中英文，提示文字放 `text/help.json`。
  F1／F2／F3／F9 繼續送原版；F5不送入原版。Shift配合前端熱鍵時不送原版，
  配合一般按鍵時先送Shift再送該鍵；單獨Shift釋放時送完整按下／放開，不移除原版Shift支援。
  HD使用獨立的Ebiten圖像與RGBA緩衝；文字、提示及其他輔助頁不可覆寫HD圖像。
  原版畫面、HD、中文及輔助頁的既定先後順序保持，來源與修正原型見研究038 §52。
- F10 的原版狀態與文字快照格式不變，不保存圖素、遮格或主題開關。
  成功 F11 後清空並從已載入資產重登記全部 Art watcher，保持本次 HD 開關，
  下一次 Frame 以載回的原版畫面重新比對；失敗讀檔不動圖面。逐步操作工具也在每次載入時
  重新建立主題，不依賴 `.xlate.json` 的圖面資產。
- 前端順序為原版 → HD → 中文 → 輔助頁／提示。Ebiten 的 `WritePixels` 要預乘 RGBA，
  因此僅在輸出 GPU 前轉換；逐步 PNG 截圖使用非預乘來源做正常透明度合成。

READY 涵蓋上述第一批及 §1.2／§1.3 的限定技術契約；完整 sprite、框架美術品質及權利分類仍按 §1.1／§7
驗收。第一批測試須包含真實來源、缺圖／錯尺寸／來源形狀／路徑越界負對照、倍率停用、
8×8 恢復、獨立語言與 HD 開關及成功讀檔重登記，不能以通用 204 測試取代。

## 5. 與中文疊字的關係

圖與字使用各自的 `xlate.Layer`；前端先畫圖面，再畫文字。
圖面層只有 Art，與中英文開關及文字快照獨立，沿用 dosgolem `204` 的介面。
圖面以 Key 更新，不同 Key 可重疊並依 Order 繪製；文字的重疊移除不作用於圖面。
面板中文與背景可以共存，角色也不會刪掉之後需要恢復的背景。

原版在 HD 圖上面畫東西時，**對應的 8×8 格破洞露出原版**（格線原點為 `(0,0)`）。
原版恢復背景時該格須重新顯示 HD；不能沿用永久透明格（`204` §2.2／§2.6）。
迷宮視野、訊息框、狀態數值、走路中的角色都靠這個機制正常顯示。

## 6. 驗收

1. **反向對照**：`-theme` 為空時，四個檢查點畫面與今天逐像素相同（差 0）。
2. **遊戲狀態不變**：同一段重播開主題與不開，結束時指令數相同、存檔逐位元組相同。
3. **破洞落在該破的地方**：迷宮畫面上，HD 疊字失效的格子集合
   ＝ 原版把 `SCREEN.PBL` 蓋掉的格子集合（拿 `docs/re/038` §3 的差異圖當預期值）。
   多破或少破都不算過。
4. **缺圖報錯**：把一個 `png` 改名，啟動要以非 0 結束並指出是哪一筆。
5. **倍率**：`-scale 2` 配 `scale: 3` 的主題 → 不載入、有提示、畫面是原版。
6. **成本**：開主題與不開，`Frame` 的耗時與每秒幀數各量一次（不設門檻，要有數字）。
7. **完整 HD 目標**：第一批以上六項通過只代表 SCREEN／MENU 接入。
   §1.1 的 sprite 仍須逐來源圖號記錄素材、規格及接入狀態，正常路徑抽測敵人、盟友及戰鬥效果，
   核對位置、遮擋、動作切換與原版遊戲狀態不變；差分貼圖、未知用途與缺素材須明示。
   單張預覽、尺寸合格或未接入的候選不能當作完成；全部納入範圍的素材驗收後才關閉 #34。
