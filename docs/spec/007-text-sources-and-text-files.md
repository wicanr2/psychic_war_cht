# 007：文字來源格式與文本檔

狀態：**READY**
日期：2026-09-17
對應：issue #16（格式）、#17（文本檔）、#19（覆蓋率）；證據 `docs/re/014`（印字路徑）、`docs/re/015`（檔案格式）

## 1. 目的

把遊戲裡**所有會被印到畫面上的固定文字**，依「來源檔＋偏移」列成一則一筆的文本檔，給翻譯與轉譯層共用：

- 翻譯看得到原文、欄寬、所在畫面的字型；
- 轉譯層在印字的那一刻用同一個 key 找譯文（`docs/re/014` §3 的字串層攔截點都拿得到來源位址）；
- 覆蓋率工具拿實跑的來源位址對帳（#19）。

不在範圍：圖檔內嵌文字（`.PBL`，#18）、執行期組出來的文字（數字、玩家名字、存檔清單的檔名）。

## 2. 版本簽章

位址表只對下列版本成立。抽取工具先驗 SHA-256，不符就停止並列出不符的檔案，不猜測。

| 檔案 | SHA-256 |
|---|---|
| `PW.EXE` | `88321206d5400b2276aba0f268e2daaa8355a733843dd9e89f9e7116ae690c49` |
| `PW_UNP.EXE`（`tools/unexepack.py` 解壓結果，不是玩家的檔案） | `fd5115b91f014c47a1fb1a6e2ecfd645e293264fe614a4b350e92637cad2fbd9` |

其餘資料檔（`I_MENU*`、`I_ENMY*`、`CODE*`）的雜湊由工具寫進 `text/sources.json`（雜湊不是原版素材）；之後的抽取以它為準。

`PW_UNP.EXE` 另外逐項驗**位元組簽章**（§3.4 的呼叫點 bytes），確認表裡的位址仍是那段程式碼。

## 3. 來源格式

字碼：20h–7Eh 是 ASCII；80h–FFh 是字型的自訂字模（`FONT.BIN` 路徑），寫成 `{XX}`；10h–1Fh 是顏色碼，寫成 `{XX}`；
< 10h 是控制碼（`docs/re/014` §6），寫成 `{XX}`。00 是結尾或填充，不寫出。

### 3.1 `I_MENUH.BIN`、`I_MENU00–11.BIN`（`FONT.BIN` 路徑）

以 16 bytes 為一列，從偏移 0 依序判讀（`docs/re/015` §2）：

| 種類 | 長度 | 判準 | 欄位 |
|---|---|---|---|
| 訊息 `message` | 32 | 前 31 bytes 都是文字（20h–7Eh 或 ≥ 80h），第 32 byte ≥ 20h 且不是選單類型碼 | 文字 31 字：第 1 行 16、第 2 行 15；第 32 byte 是類型碼，高 4 位元 & 7 是顏色（`0161:5D64`） |
| 選單提問 `menu` | 32 | 同上，但第 32 byte ∈ `qQ123456789` | 同訊息 |
| 選單選項 `option` | 16 | 緊接在提問之後；bytes 0–5 是條件區、6–15 是 10 字標籤；標籤遇 00 截斷 | 標籤 10 字 |
| 選單結束 | 16 | `00 00 00` ＋ 13 個空白，或整列只有空白與 00 | — |

判讀不了的非空列要列出（目前全部 13 個檔案 0 列）。

### 3.2 `I_ENMY00–11.BIN`（`FONT.BIN` 路徑）

80 bytes 一筆；偏移 +2 起 10 bytes 是敵人名稱（尾端 00 截斷）。名稱全空的一筆不輸出。

### 3.3 `CODEH.BIN`、`CODE0–11.BIN`（`FONT.BIN` 路徑）

腳本位元組碼。指令 **81h** ＝ 以緊接的位元組當 `ds:BX` 呼叫 `sub_167B2`，印到 00 為止，直譯器從 00 之後繼續（`cs:2612` 指令表第 1 項 ＝ `26F2`：`E8 AD 3B C3`）。

- 抽取：每個 81h 位元組之後到 00 的內容算一則 `inline`（13 個檔案共 146 個 81h，全部都接得上「文字或顏色碼到 00」，沒有例外）。
- ⚠ 沒有完整解碼位元組碼，81h 出現在運算元裡的可能性無法排除；判準是「之後到 00 全是文字或顏色碼、長度 ≤ 80」，不符的 81h 要列出（目前 0 個）。
- 只有顏色碼或空白的一則照樣輸出，`translatable: false`。
- **載入視窗**：遊戲以「要 5000 bytes」讀檔，但後面載入的檔會蓋掉尾端（probe `-reads-of .BIN` 的讀檔紀錄）：
  `CODEnn` 載在線性 `11C16`，`I_MENUnn` 接著載在 `12316`，所以只有前 **700h** bytes 有效；`CODEH` 載在 `14816`，`FONT.BIN` 接著載在 `15A16`，只有前 **1200h** bytes 有效。
  視窗外的一則標 `reachable: false`（目前 70 則，內容全部與視窗內的某一則相同：`CODEH` 3000h 之後、`CODE11` 700h 之後）。
- 內容相同的一則，`same_as` 指向第一次出現的 key（譯文共用）。

### 3.4 `PW_UNP.EXE` 內嵌文字

位址是執行期段 `0161` 的偏移（`cs:XXXX`，IDA ＝ `10510h ＋ XXXX`）。

| 範圍 | 格式 | 字型 | 印字常式與簽章 |
|---|---|---|---|
| `0287`、`0327`、`03C7` | 160 bytes（8 行 × 20） | 小字型 | `0788`；呼叫點 `01DA`、`0207`、`022B` 為 `E8 xx xx`，前面 `BB` ＋ 位址 |
| `0467`、`0495` | 到 00 | 小字型 | `07C1`；`025A`、`0266` |
| `0BD7` | 47 行 × 20 bytes | 小字型 | `0BA3`、`124B`；`0B50`、`11F8` 為 `BB D7 0B` |
| `65A9`、`65E5`、`6621`、`656D`、`665D`、`6699`、`89B3`、`8A4D`、`8AEF`、`B07D` | 60 bytes（3 行 × 20） | 小字型 | `B016`；位址前一道是 `BB` ＋ 位址（`665D`／`6699` 是 `6403`／`6409`） |
| `8851`、`88A8`、`88D1`、`88FA`、`8923` | 20 bytes | 小字型 | `B058`（複製到 `B07D` 的第 1 行後印整塊） |
| `66F7` | 11 筆 × 8 bytes（盟友名） | 小字型 | `6504`：`81 C3 F7 66` |
| `674F` | 7 筆 × 8 bytes（基地名） | 小字型 | `6504`：`81 C2 4F 67` |
| `08D7`、`0901`、`092B`、`0955`、`097F`、`0A40`、`0A6A`、`0A94` | 到 00 | `FONT.BIN` | `sub_167BF`；位址前一道是 `BB` ＋ 位址 |
| `4AC3`、`4AFB` | 到 00（`call 6294` 之後緊接） | `FONT.BIN` | `4AC0`、`4AF8` 為 `E8` 到 `6294` |

- 行的切分只是版面資訊（`lines` 欄位），一則的 key 以區塊起點為準。
- 防拷的 ESP 答案（`cs:6787` 指標表）是比對用的字串，不印在畫面上，不輸出。

### 3.5 `I_MAP00–11.BIN` 的地點名稱（`FONT.BIN` 路徑）

- 1,024 bytes 的地圖檔（`docs/re/011` §3），偏移 **200h** 起 64 筆 × 8 bytes，第 i 筆是地點編號 i 的名稱（狀態欄 PLACE）；00 截斷，整筆空白不輸出。
- 名稱混用 ASCII 與 `FONT.BIN` 的自訂字模（例：`{95}{A5}{B5}{C5}{D5}{96}{A6}` 畫出來是「Landing Pad」）。
- 遊戲把名稱複製到腳本緩衝區（線性 `16816`）再以 `sub_167B2` 印出；12 個檔共 293 筆。
- 等級：強證據（實跑印出的位元組序列在最近載入的 `I_MAPnn` 名稱表裡；複製的程式碼沒有讀）。

## 4. 文本檔（`text/`）

一個來源檔一份 JSON，檔名 `text/<來源檔名>.json`（`PW.EXE` 的內嵌文字叫 `text/PW.EXE.json`）：

```json
{
  "schema": "psychic-war-text/1",
  "source": "I_MENUH.BIN",
  "sha256": "5c3ca372…",
  "entries": [
    {
      "key": "I_MENUH.BIN:0530",
      "kind": "message",
      "font": "font8",
      "width": 31,
      "lines": [16, 15],
      "type": "P",
      "translatable": true,
      "same_as": "",
      "original": "You can't move  forward here.  ",
      "translation": "",
      "note": ""
    }
  ]
}
```

| 欄位 | 意義 |
|---|---|
| `key` | `<來源檔名>:<偏移 4 位十六進位>`；`PW.EXE` 用 `PW.EXE:cs:XXXX` |
| `kind` | `message`、`menu`、`option`、`enemy-name`、`place`、`inline`、`block`、`line`、`names` |
| `font` | `font8`（`FONT.BIN`）或 `font6`（小字型） |
| `width` | 原版可用的字數（位元組數） |
| `lines` | 原版的行寬切分（沒有切分時省略） |
| `translatable` | 去掉顏色碼、控制碼、空白後有沒有文字 |
| `reachable` | 在載入視窗內（§3.3）；只有 CODE 會是 false |
| `original` | 原文。⚠ 原版素材 |
| `translation` | 譯文，空字串 ＝ 還沒翻 |

- **重建時保留譯文**：工具以 key 合併，已有的 `translation`、`note` 不覆蓋；原版沒有的 key 保留並標 `"orphan": true`。
- 原文欄位規則：本 repo private 期間可以進版控；公開前改成建置時從玩家的檔案重建（`check` 子命令已能逐筆驗證原文可重建，§5）。

## 5. 工具（`tools/text_extract.py`）

| 子命令 | 做什麼 |
|---|---|
| `build <原版目錄>` | 驗 §2 簽章 → 抽出全部來源 → 合併寫入 `text/*.json` 與 `text/sources.json`；印每個來源的則數 |
| `check <原版目錄>` | 重新抽取，與 `text/` 的 `original` 逐筆比；不同或缺少就失敗 |
| `stats` | 只讀 `text/`：總則數；**要翻則數**（`translatable`、`reachable`、`same_as` 為空）；已翻則數 |
| `menu`／`enmy`／`code` | 既有的單檔列印（除錯用） |

缺原版目錄或缺任一來源檔：錯誤結束並列出缺的檔名。

## 6. 覆蓋率量測（`tools/text_coverage.py`，#19）

### 6.1 實跑紀錄

`tools/text_coverage.sh [重播檔]` 用 `tools/states.sh` 跑重播，每段 probe 加：

```
-reads-of .BIN
-regs-at 0161:6289,0161:62A2,0161:62AF -regs-max 200000
-call-args 0161:B0F1:1:0:<大數> -arg-regs
```

紀錄複製到 `workplace/coverage/<重播檔名>/`（每段一份 `.log`）。

### 6.2 換算成 key

- **載入表**：依重播檔的 `from` 串接，前一段結束時的載入表傳給下一段；段內依步數套用讀檔事件（檔名、線性起點、實得 bytes）。
  某個線性位址屬於「步數在前、最後一次覆蓋它的讀檔」。
- **`FONT.BIN` 字串層**：三個位址都是迴圈頭。同一常式、BX 連續加 1（`6289` 另要 CH 少 1）的命中併成一次印字；起點線性位址：
  `6289`、`62A2` 是 `DS×16 ＋ BX`；`62AF` 是段 `0161` 偏移 BX。第 k ≥ 1 次命中的 AL 是第 k−1 個字元（用來核對內容）。
  - 落在文字來源檔（`I_MENU*`、`CODE*`）：偏移 o，依序找 key `o`、`o−16`（訊息第 2 行）、`o−6`（選項標籤）。
  - `62AF` 偏移 `3A4C`：戰鬥時從 `I_ENMY` 複製來的敵人名稱，以內容對最近一次載入的 `I_ENMY` 檔。
  - `62AF` 其他偏移：key `PW.EXE:cs:<偏移>`。
  - `62A2` 起點在腳本緩衝區 `16816–16915`：內容含字母或 ≥ 80h 字碼時，以內容對最近一次載入的 `I_MAP` 名稱；只有數字與空白算執行期產生。
- **小字型**：`B0F1` 每字一筆，依返回位址取來源指標：`B02A`、`07A0`、`07D1`、`653A` 是 BX；`0BB1`、`1259` 是 BX − 1；`654E` 是 DX；
  `B055` 是輸入回顯與選擇游標（執行期產生）。指標落在某則 `PW.EXE` 的 `[位址, 位址＋寬度)` 就算觸發該則；
  落在 `B07D` 第 1 行（由 `B058` 複製）時，以該行 20 字的內容對 §3.4 的 20 bytes 行。
- **歸類**：
  - 觸發：換算到 key（`same_as` 換成根 key）；
  - 執行期產生：起點不落在任何文字來源、也不是 `PW.EXE` 的表列位址，而且是數字、玩家輸入、`B055`；逐一列出位址與內容；
  - **觸發了卻不在文本檔**：落在文字來源或 `PW.EXE` 程式碼段、含字母、卻換算不到 key；或起點不屬於上兩類的含字母字串。

### 6.3 輸出

四個數字：要翻則數、已翻則數、實跑觸發則數（其中要翻的）、觸發了卻不在文本檔的則數；外加執行期產生的清單。
第四個數字不為 0 時，逐筆列出段名、步數、位址、內容，結束碼 1。

## 7. 驗收

1. `build` 在簽章相符時產生 `text/`：I_MENU 訊息 427、選單 95、選項 273；I_ENMY 名稱 60；I_MAP 地點名稱 293；CODE 81h 146；PW.EXE 內嵌依 §3.4 的項數。與 `docs/re/015` 的數量一致。
2. 反向對照：把一份 `I_MENU` 的副本改掉 1 byte，`build` 因雜湊不符停止並指出檔名。
3. `check` 對剛建好的 `text/` 通過；手改一則 `original` 後失敗並指出 key。
4. 合併：在一則填譯文後重跑 `build`，譯文保留。
5. `PW_UNP.EXE` 位元組簽章：把表中一個呼叫點的位址改錯，`build` 失敗並指出項目。
6. 實跑核對：`docs/re/015` §5 的 41 行訊息與 12 則畫面抽樣，都能以 key 在 `text/` 找到。
7. `CODEH` 3000h 之後、`CODE11` 700h 之後的一則 `reachable` 為 false；反向對照：視窗內的一則為 true。
8. 覆蓋率：重播 18 段輸出四個數字，「不在文本檔」為 0；出發平台的提問 `I_MENUH.BIN:09F0`、防拷的 `PW.EXE:cs:65E5`、方位 `CODEH.BIN:02B4`、地點名稱 `I_MAP01.BIN:0228` 在觸發清單裡。
   反向對照：從 `text/` 拿掉 `I_MENUH.BIN:09F0`（暫存副本），「不在文本檔」變成 ≥ 1 並列出它。

## 8. 不做

- 圖檔內嵌文字（#18）、譯名表（#23）。
- 位元組碼的完整解碼；選單條件區與類型碼低 4 位元的意義。
- 執行期產生的文字（數字、名字、檔名）。
