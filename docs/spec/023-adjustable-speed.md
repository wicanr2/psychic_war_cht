# 023：遊戲內可調執行速度

狀態：**READY**
日期：2026-09-19
對應：issue #40
前置：`docs/spec/004`（預設速度 750 cycles）、`docs/spec/006`（前端節拍）、
`docs/spec/012`（輔助熱鍵）、`docs/re/009`／`010`（戰鬥綁 CPU）、`docs/re/037`（戰鬥偵測）

## 1. 決定

**只有非戰鬥的部分變快，戰鬥一律維持原速**（使用者定案 2026-09-19）。

檔位是原速的整數倍：**1×（原速）、2×、3×**。原速就是 `-cycles` 給的值（預設 750，`docs/spec/004`）。
熱鍵 **F12** 循環切換。檔位存進設定檔，下次啟動沿用。

理由：戰鬥敵我雙方的推進都綁 CPU 指令數而不是計時器（`docs/re/009` §5、`docs/re/010` §1），
整體調快會直接改變戰鬥難度。迷宮移動與文字輸出同樣綁 CPU，但它們沒有對手，變快只是省時間。

## 2. 檔位怎麼實作（關鍵決定）

**檔位只改「一毫秒牆上時間要跑幾個 cycle」，不改機器本身。啟動之後不再呼叫
`SetDOSBoxCycles`。**

`SetDOSBoxCycles(perMs)` 會把 `CPUHz` 設成 `perMs × 1000`，而 IRQ0 的間隔是從 `CPUHz`
算出來的（dosgolem `198-dosbox-cycles` §4）。**計時器中斷插在戰鬥迴圈的哪個位置會改變
單場戰鬥的結果**——只改 IRQ0 的排程方式，12 組裡有 8 組玩家損血就變了（`docs/re/010` §4.5）。
所以只要換檔會動到 `CPUHz`，「戰鬥不受檔位影響」就不可能成立，也量不出來。

改成只動節拍之後：

- 機器的 `CPUHz`、IRQ0 間隔、每一個排程決定都與檔位無關，**同一份輸入在任何檔位下逐位元組相同**。
  「戰鬥長度不受檔位影響」變成結構上的保證，不是靠偵測補出來的。
- 重播檔（`docs/spec/019`）記的是指令數，換檔不影響重播。`cycles` 欄位照舊記原速。
- 代價：檔位 n 時機器時間走得比牆上時間快 n 倍，所以**配樂與音效會跟著快 n 倍**（§5）。

作法：前端維持一個「虛擬牆上時鐘」，每一幀加上 `實際經過的毫秒 × 目前倍率`，
再餵給既有的 `Pacer`（`docs/spec/006` §3.2）。`Pacer.MaxCatchUpMs`（100 機器毫秒）不變，
所以倍率大到一幀要跑超過 100 機器毫秒時會被截掉；1×／2×／3× 一幀最多 50 毫秒，不會碰到。

## 3. 戰鬥判斷點與它的邊界

判斷點與證據見 `docs/re/037`。摘要：

| 事件 | 掛鉤（`oracle.OnCall`）| 說明 |
|---|---|---|
| 進入戰鬥 | `0161:47D4` | 戰鬥主迴圈 `sub_14CE4` 的進入點（IDA `14CE4`）|
| 離開戰鬥 | `0161:47AD` | `call sub_14CE4` 的返回點（IDA `14CBD`）；打贏與 F3 逃走都會走到 |
| 讀狀態檔之後 | 讀 `0x509C` | 掛鉤在載入時不會觸發，改由敵人 HP 不為 0 重推 |

邊界（都量過，數字在 `docs/re/037` §4）：

1. **進入點在戰鬥畫面畫好之後、戰鬥迴圈跑第一圈之前。** 轉場那約 0.24 秒的繪圖跑在玩家
   選的檔位上，戰鬥本身一圈都不會。
2. **離開點在敵人 HP 歸零之後 5.6 萬步，但比迷宮畫面回來早 2.2～2.9 秒。**
   那段畫面是靜止的（敵人已擦掉、沒有文字），加速只會讓停頓變短。
3. **讀狀態檔的重推會把「F3 逃走之後殘留的敵人 HP」誤判成戰鬥中**，
   一路維持原速到下一場戰鬥結束為止。誤判方向是慢，不會讓戰鬥變快。
4. **玩家陣亡沒有驗過**（假說：同樣從 `sub_14CE4` 返回）。即使不觸發，殘留狀態是一直原速。

⚠ 位址是這一版 `PW.EXE` 在 dosgolem 上的執行期位址，屬於本 repo（`CLAUDE.md` 的分層）。

## 4. 熱鍵與切換時機

**F12 循環：原速 → 2 倍 → 3 倍 → 原速。**

選 F12 的理由：

- F1／F2／F3／F9 是原版的功能鍵（`docs/re/036`），F4–F8、F10、F11 已經用掉
  （`docs/spec/012`、`014`、`015`）。
- **F12 目前不在 `scanCodes` 裡**，也就是說原版從來就收不到這個鍵，攔下它不會拿掉任何原版功能。
  說明書 p.8 列的功能鍵也沒有 F12。
- 攔一個鍵之前要先確認原版沒在用它（`docs/re/036` §3 的規則）。這一條在這裡成立。

切換時機：

- **戰鬥中按 F12 不會變速。** 記下玩家選的檔位，畫面上說明「戰鬥中維持原速」，
  等戰鬥結束再生效。
- 進入戰鬥時立刻降回原速；離開戰鬥時立刻回到玩家選的檔位。兩邊都是瞬間切換，
  不做漸變——漸變只會讓「戰鬥是不是真的原速」變得無法量測。

## 5. 音訊

檔位 n 時機器每一秒牆上時間產生 n 秒份的取樣，全寫進環形緩衝會一直溢位。多的要抽掉。

**抽多少看牆上時間，不看檔位**：前端追不上時會放棄一部分虛擬時間（`Pacer.DroppedMs`），
機器其實沒跑到 n 倍，照 n 抽會抽掉本來聽得到的聲音，變成快轉時一直破音。
作法是「這一幀的牆上秒數 × 取樣率」當額度，超過就平均抽，沒用完的額度留到下一幀
（不留的話每一幀都被削掉尖峰、補不回低谷，原速下也會累積成持續欠載）。
額度最多累到半秒，與環形緩衝同尺寸。

不做重新取樣（會需要濾波器，而快轉時的音質不值得）。原速而且主機跟得上時，
額度一定夠，整批原樣寫進去，這條路徑等於不存在。聽起來就是一般模擬器快轉的聲音
（音高與節奏都是 n 倍）。

## 6. 設定檔

`<scratch>/settings.json`（`scratch` 就是即時存檔的目錄，`docs/spec/021` §3.2）：

```json
{"schema": "psychic-war-settings/1", "speed": 2}
```

- 讀不到、格式不對、或 `speed` 不在檔位清單裡 → 用 1×，不報錯（設定檔壞掉不該擋住遊戲）。
- 每次切換就寫回去。寫失敗只記一行紀錄，不影響遊戲。
- 命令列 `-speed <n>` 蓋過設定檔，也不寫回去（驗收與反向對照要能指定檔位而不污染玩家設定）。

## 7. 畫面上看得到

- **切換時**：底部提示列兩秒（與 F5／F10 同一條路），例如「速度 2 倍」、
  戰鬥中則是「速度 2 倍（戰鬥維持原速）」。
- **持續顯示**：檔位不是原速時，畫面左上角常駐一小塊字，內容是「2 倍」或
  戰鬥中的「2 倍→原速」。原速時不畫，不佔畫面。
- **說明頁**（F4，`text/help.json`）列出 F12 與「戰鬥不變速」這件事。

## 8. 驗收

1. **單元測試**（`apps/psychicwar`）：
   - 檔位循環、戰鬥中 `Effective()` 一律回 1、戰鬥結束後回到玩家選的檔位。
   - 設定檔讀寫往返；壞掉的設定檔回 1× 而不是錯誤。
   - 音訊額度：3 倍時一幀只寫得下 1/3 的取樣且是平均抽的；主機只跑到 1.5 倍時
     抽掉的比例要跟著變小（不是照檔位抽）；上一幀沒寫滿的額度下一幀補得回來。
   - F12 要被攔下（`Intercepted`），而且**不可以有掃描碼**。
     F1／F2／F3／F9 仍然不可以被攔（`docs/re/036` 的回歸斷言保留）。
2. **非戰鬥變快（要有秒數）**：Xvfb 前端從 `07-first-play.state` 起，按住 Up 走 5 格，
   量走完的牆上秒數與每格秒數，1× 與 3× 各一次。比值要接近 3。
   ⚠ Xvfb 是軟體算繪，成本比模擬本身高；主機跟不上時比值會偏低，
   偏差方向是「加速幅度看起來比較小」，通過就算數（同 `docs/re/010` §4.6）。
3. **戰鬥長度不受檔位影響（核心宣稱）**，三個互補的量法：
   - **不按任何鍵**，從 `08-encounter.state`（戰鬥中）跑固定秒數，1× 與 3× 各一次，
     比跑到的指令數。**要相同（差 ≤ 1%）**。沒有輸入所以完全決定性，這一項最乾淨。
     對照組：同樣不按鍵、改從 `07-first-play.state`（迷宮）跑，指令數要差約 3 倍。
   - 按住空白鍵打完第一場，比「戰鬥結束事件」的指令數、牆上毫秒與機器毫秒。
     **戰鬥區間的 `機器毫秒 ÷ 牆上毫秒` 在兩個檔位下都要是 1.00（±0.02）**——
     也就是不論玩家選哪一檔，一場 N 個 cycle 的戰鬥都要花 N ÷ 750000 秒。
     ⚠ 指令數相同是**加分不是判準**：xdotool 的按鍵落在哪一個指令數有抖動，
     而計時器中斷的相位會讓同一場戰鬥差到 ±30%（`docs/re/010` §4.5）。
     兩次剛好相同時可以當強證據，不同時要先確認是不是抖動造成的，不能直接判失敗。
   - 機器層的決定性由 dosgolem 保證（同一狀態＋同樣的指令數時點 → 逐位元組相同），
     檔位的程式路徑完全不碰 `SetDOSBoxCycles`，所以「同一份輸入」的等價性是結構上的，
     不靠這裡的量測補。
4. **反向對照**：檔位是原速時行為與改動前相同——`tools/frontend-hotkeys-check.sh`
   全部通過（含說明頁逐像素）、畫面上不畫常駐標記。
5. `tools/go-ebiten.sh test ./apps/... ./cmd/...` 全過。

量測腳本：`tools/frontend-speed-check.sh`（第 2、3 項）、`tools/speed_report.py`（判讀）。
數字記在 `docs/re/037` §6。

## 9. 不做

- 非整數倍（1.5×）。音訊抽樣要整數，而且檔位越多玩家越難知道自己在哪一檔。
- 慢動作（0.5×）。原版在 240 cycles（XT）已經是最慢的合理值，用 `-cycles xt` 就有。
- 快轉鍵（按住才快）。循環檔位已經涵蓋，多一個模式就多一組要驗的邊界。
- 把檔位寫進重播檔。檔位不影響機器執行，重播不需要知道。
