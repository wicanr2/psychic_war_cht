# 002：OPL2（AdLib）配樂的比對方法

狀態：**READY**
日期：2026-09-17
對應：issue #5；dosgolem 合成器規格 `196-opl2-synth-skeleton`

## 1. 目的

驗證 dosgolem 的 `.MID` 路徑在**節奏與音高**上與 DOSBox-X（OPL2）一致。
dosgolem 的合成器是雛形（音色近似、震音／顫音／KSL 沒做），所以不比音色、不比波形。

OPL2 是複音：同一時間可有多個聲道發聲，`001` 的過零點切段不適用。

## 2. 參照

**暫存器寫入序列是樂譜**（dosgolem `-opl-log`）：每個 Key-On（`B0h`–`B8h` bit 5 由 0 變 1）得到
「時間、聲道、頻率 `FNum × 49716 ÷ 2^(20 − Block)`」。時間以 dosgolem 的 `StepsPerSecond` 換算。
相差 ≤ 15 ms 的 Key-On 視為同一個起音群組。

兩份 WAV（dosgolem `-dump-opl-wav`、DOSBox-X 錄音）都拿這份樂譜去檢查，用同一支程式。

## 3. 檢查

`tools/music_compare.py opl`：

1. **起音函數**：每 10 ms 一格，算 20 ms 視窗的能量；起音強度 ＝ `max(0, log(能量) − log(前一格能量))`。
2. **對齊**：WAV 的起音函數與樂譜的起音脈衝序列做互相關，搜尋 −5 到 ＋15 秒的位移，取最大值。
3. **節奏**：每個起音群組，在 WAV 起音函數上 ±30 ms 內找峰值；峰值高於「全曲**正值**起音強度的第 75 百分位」才算「有起音」（起音函數大多是 0，不排除 0 的話門檻會是 0）。
   對有起音的群組，以「WAV 峰值時間 對 樂譜時間」做線性回歸。
4. **音高**：每個 Key-On，取起音後 30–130 ms 的視窗，以 Goertzel 演算法量頻率 f 的能量 P(f)，
   與 f 上下各一個半音的能量平均比較：`P(f) ≥ 2 × 平均` 算「音高在場」。
   同群組多個音各自判定。頻率低於 60 Hz 或高於 4 kHz 的音不列入（視窗太短或超出錄音頻寬）。

## 4. 判準

| 指標 | 通過 |
|---|---|
| 起音命中率（群組） | ≥ 90% |
| 音高在場率（Key-On） | ≥ 80% |
| 速度：回歸斜率 | 與 1 相差 ≤ 0.5% |

兩份 WAV 分別判定。dosgolem 那份是合成器對自己樂譜的自我檢查（應遠高於門檻）；
DOSBox-X 那份才是與另一個實作的比對。

門檻比 `001` 寬：FM 音色有泛音與調變、複音會互相遮蔽、DOSBox-X 以牆上時間混音。
門檻在執行前定案，不依結果調整；不通過時照實記錄並寫出是哪一項。

## 5. 輸出

JSON：樂譜 Key-On 數與群組數、對齊位移、兩份 WAV 各自的起音命中率、音高在場率、斜率、起音殘差分位數、
未命中群組與未在場音的前 20 筆（時間、頻率）。

## 6. 不做

- 音色、音量包絡、震音／顫音的比對。
- 節奏模式（打擊樂）：案例沒有使用。
