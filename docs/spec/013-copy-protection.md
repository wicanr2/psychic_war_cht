# 013：防拷畫面（中文化、F1 查表、略過）

狀態：**READY**
日期：2026-09-18
對應：issue #28
證據：`docs/re/028`；相關 `docs/re/003` §2.2（行為觀察）、`docs/spec/012`（F1）

## 1. 原版的機制（靜態讀出來的）

| 位址（`0161:`） | 角色 |
|---|---|
| `6391` `sub_168A1` | 防拷主流程：出題 → 讀答案 → 比對 → 過關或重來 |
| `644C` `sub_1695C` | 出題：亂數選盟友（11 選 1）與基地（7 選 1），把**正確答案**（超能力名稱）複製到 `cs:66E5`（16 bytes，空白補滿） |
| `6493` `sub_169A3` | 讀玩家輸入，放在 `cs:66D5`（16 bytes） |
| `cs:6787` | 答案表：11×7 個 u16 指標，指向超能力名稱字串 |
| `cs:66F5`、`cs:66F6` | 這一題的盟友編號與基地編號 |
| `cs:66F7` 起 | 11 個盟友名（8 bytes 一個）；`cs:674F` 起 7 個基地名 |

**這一版的比對是關掉的**：`0161:63B3` 的 `cmp al, ah` 之後是 `jmp short`（`EB 11`）而不是條件跳躍，
16 個字元一律當成相同，所以**任何答案都會過**（空白也會過，與 `docs/re/003` 的行為觀察一致）。
`63B7` 起的「轉大寫再比一次、錯兩次就趕出去」那段是**到不了的死碼**。

## 2. 中文化要做的三件事

### 2.1 畫面中文化

防拷畫面的文字走小字型路徑，已經由 `docs/spec/009` 的疊字處理（提問、盟友名、基地名）。
**玩家要輸入的答案維持英文**：原版比對的是 ASCII，而且這一版根本不比對。

### 2.2 F1 查表

F1 說明頁（`docs/spec/012` §3）在**防拷畫面**時多一行：

```
本題答案：FREEZE
```

- 答案從**玩家自己的執行檔在記憶體裡的那 16 bytes**（`cs:66E5`）即時讀出來，不散布原版資料。
- 判斷「現在是防拷畫面」：那 16 bytes 全是可印字元、去掉尾端空白後長度 ≥ 3 且只含大寫字母、數字與 `-`。
  不符就不顯示這一行（一般畫面上那塊記憶體不是答案）。

### 2.3 略過

這一版任何答案都會過，所以**不另外做開關**；說明頁寫明「直接按 Enter 也會過」（已經有）。
若之後拿到比對沒被改掉的版本，再加一個「略過」選項，作法是在 `63B3` 之後把比較結果強制成相等
（`oracle.SetRegs`，不改原版檔案）。

## 3. 驗收

1. 單元測試：`ProtectionAnswer` 對 `"FREEZE          "` 回 `FREEZE`；對空白、含小寫、含控制碼的 16 bytes 回空字串。
2. 實跑：從 `03-protection` 狀態按 F1，說明頁出現「本題答案：FREEZE」，與 `cs:66E5` 的內容相同；
   關掉 F1 之後畫面與開啟前逐像素相同。
3. 反向對照：在迷宮畫面（`07-first-play`）按 F1，說明頁**沒有**那一行。

## 4. 不做

- 把答案表整份印出來（那是原版資料，而且玩家只需要當下這一題）。
- 修正原版被改掉的比對（要保持與玩家手上的執行檔一致）。
