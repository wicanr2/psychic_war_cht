# 017 — 輸入名字（只支援 ASCII）

狀態：**READY**
日期：2026-09-18
對應 issue：#26
前置：`docs/spec/009`（疊字）、`docs/re/014`（印字常式）、`docs/re/008`（存檔）

---

## 1. 決定

**玩家輸入的名字只支援 ASCII（使用者定案 2026-09-18）。**

原版在 `ENTER YOUR NAME:` 收玩家輸入，存檔檔名直接用這個名字（`<名>.DAT`，`docs/re/008`），
畫面上的狀態頁也用它。中文名字要能用，得同時處理三件事：原版的固定寬度欄位、DOS 8.3 檔名、
以及原版自己畫名字的那段程式碼。代價不成比例，所以不做——**提示文字中文化，名字本身維持 ASCII**。

不做的那條路（留記錄）：顯示層把中文名字轉成 ASCII 代號存檔。它會讓存檔檔名與玩家看到的名字不一致，
玩家在檔案總管裡找不到自己的存檔。

## 2. 現況（第 8 輪抽測已驗）

| 項目 | 狀態 |
|---|---|
| 提示「請輸入你的名字：」 | 已中文化（`text/PW.EXE.json`，疊字層蓋在原版英文上） |
| 玩家輸入的字元 | 原版自己畫，疊字層不蓋——`xlate.Stamp` 的 `Transparent` 就是為此（`docs/spec/009`） |
| 狀態頁的「姓名」 | 顯示玩家輸入的 ASCII |
| 存檔檔名 | `<名>.DAT` |

前端把 `ebiten.Key` 對到掃描碼（`apps/psychicwar/keymap.go`）送給原版的 `INT 09h` 處理常式。
**中文輸入法送出的是字元不是掃描碼，所以本來就進不到遊戲裡**——玩家按半天沒有反應，
而畫面上不會說為什麼。

## 3. 規格

1. 名字只接受 ASCII，與原版行為相同（前端不另外加限制，也不另外放寬）。
2. **收到非 ASCII 的文字輸入時要講出來**：前端用 `ebiten.AppendInputChars` 看有沒有非 ASCII 字元，
   有的話顯示提示「名字只能用英數字（原版的限制）」。
   這是「沒有翻譯的字串要看得出來」同一條原則的延伸：**被擋掉的輸入不能靜默消失**。
3. 提示用 `text/help.json` 的字串，不寫死在程式裡——寫死的中文收不進字型子集，畫出來會缺字
   （`docs/re/030` §2 的教訓）。
4. 提示只在畫面上出現幾秒（與其他熱鍵提示相同的 toast），不擋輸入、不改記憶體。

## 4. 驗收

1. 名字一致：逐步試玩輸入 `PLAY3` 之後，記憶體的名字欄位是 `play3`（原版轉小寫、空白補齊），
   狀態頁顯示同一個名字，即時存檔讀回來仍相同。
   ⚠ 這一項要用 **pwstep 的逐步試玩**（`workplace/playtest/play3` 第 013–014 步），不要用實時前端：
   前端的轉場比逐步操作快，等固定秒數送鍵會整串錯位——實測第 6 個 Return 之後畫面已經在迷宮，
   名字被空的確認掉，字母全送在迷宮裡。
2. 非 ASCII：送一個中文字元進前端，**記憶體中的名字欄位沒有變化**（`lin:1699A` 起 8 bytes 與送之前相同）。
3. 判斷本身：`NonASCII` 對空字串、ASCII、中文、全形空白的結果（單元測試）。
4. 提示文字在 `text/help.json` 裡，`tools/font/bake.sh` 收得到它用到的字。

⚠ **「畫面上出現提示」在容器的 Xvfb 上驗不到**：xdotool 要送 Unicode 字元得重映射鍵盤，
這個 X server 上會回 `xdo_enter_text_window reported an error`。
`tools/frontend-name-check.sh` 在送不出去時會印出來說沒驗到，**不假裝通過**；
判斷邏輯由單元測試涵蓋，顯示那一段與 F10／F2 用的是同一個 toast。

## 5. 不做

- 中文名字（見 §1）。
- 名字欄位的長度放寬（原版 8 字元，改了會動到存檔格式）。
