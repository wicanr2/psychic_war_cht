# 028：防拷的機制與 F1 查表

狀態：量測紀錄（2026-09-18）。對應 issue #28。規格 `docs/spec/013`；行為觀察見 `docs/re/003` §2.2。

## 1. 結論

| 事實 | 等級 |
|---|---|
| 出題 `sub_1695C`（`0161:644C`）：亂數選盟友（11 選 1）與基地（7 選 1），把**正確答案**（超能力名稱）複製到 `cs:66E5`（16 bytes，空白補滿） | confirmed（靜態＋實跑讀記憶體） |
| 答案表在 `cs:6787`：11×7 個 u16 指標，指向超能力名稱字串 | confirmed |
| 盟友名 11 個從 `cs:66F7` 起（8 bytes 一個）、基地名 7 個從 `cs:674F` 起 | confirmed |
| 玩家輸入放 `cs:66D5`（16 bytes），由 `sub_169A3`（`0161:6493`）讀 | confirmed |
| **這一版的比對被關掉**：`0161:63B3` 的 `cmp al, ah` 後面是 `jmp short`（`EB 11`）而不是條件跳躍，任何答案都會過 | confirmed（靜態＋空白答案實測會過） |
| `0161:63B7` 起「轉大寫再比一次、錯兩次就趕出去」是到不了的死碼 | confirmed |

**一個位元組的差別**：條件跳躍 `74 11` 與無條件跳躍 `EB 11` 只差第一個 byte。
所以這個發行版（或它的來源）把防拷的判定拿掉了——不是我們的執行器行為不同。

## 2. F1 查表怎麼做

- 答案**不寫進本專案**，從玩家自己的執行檔在記憶體裡的那 16 bytes 即時讀（`cs:66E5`）。
- 「現在是不是防拷畫面」不能看那塊記憶體的內容判斷：**過關之後答案還留在那裡**，
  一開始用「內容看起來像答案」當條件，結果迷宮畫面按 F1 也會跳出上一題的答案。
  改成掛在輸入常式上：`sub_169A3` 進入（`6493`）時設旗標、`retn`（`6503`）時清掉，
  只有玩家正在輸入答案時才顯示那一行。
- 規則：**「記憶體裡還留著」不等於「現在正在用」**。要判斷狀態就掛在改變狀態的那段程式上，不要從殘留的資料反推。

## 3. 驗收（`docs/spec/013` §3）

| 項目 | 結果 |
|---|---|
| 單元測試 `ProtectionAnswer` | 通過（正常答案、含連字號、空白、小寫、太短、控制碼、標點、長度不足） |
| 實跑：`02-match` → Enter 進防拷畫面 → F1 | 說明頁多出「本題答案：FREEZE」 |
| 交叉驗證：畫面上的題目是「敏頓 × 梅爾瑟」（盟友 2、基地 6） | 答案表 `[2][6]` ＝ `FREEZE`，與畫面顯示相同 |
| 反向對照：迷宮畫面（`07-first-play`）按 F1 | 說明頁與 `text/help.json` 算出的期望值差 **0**（沒有那一行） |
| 略過 | 這一版任何答案都會過（空白也會），不另外做開關；說明頁已寫明 |
