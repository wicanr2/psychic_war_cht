# 032：OPL2 合成器的保真度——判準定案與現況

狀態：量測紀錄（2026-09-18）。對應 issue #5。判準 `docs/spec/016`（READY）；合成器 dosgolem `196-opl2-synth-skeleton`。

## 1. 結論

**判準通過（2026-09-18）。** 差距的根源是**相位單位**：真機把相位當成波表索引，
一個正弦週期是 **1024** 個索引，而第一版的公式當成 512 在算——FM 少了一半、回授多了一倍。

| 項目 | 結果 |
|---|---|
| 驗收判準 | 定案（`docs/spec/016`）：`spec` ≥ 0.8350、`env` ≥ 0.7548、`chroma` ≥ 0.9603 |
| 合成器補上 | KSL、震音、顫音、指數起音（dosgolem `196` 修訂） |
| 相位尺度修正 | FM `4π` → `8π`、回授 `2^(FB−4)` → `2^(FB−5)` |
| **全曲前 30 秒** | `spec` **0.9117**、`env` **0.8119**、`chroma` **0.9836** → **三項全過** |
| 前 45 秒 | `spec` 0.8661、`env` 0.7993、`chroma` 0.9798 → 仍全過 |

修正前後（前 30 秒）：

| 版本 | `spec` | `env` | `chroma` |
|---|---:|---:|---:|
| 修正前 | 0.8086 ✗ | 0.7007 ✗ | 0.9730 ✓ |
| 只改回授 | 0.8270 ✗ | 0.7431 ✗ | 0.9736 ✓ |
| 只改 FM | 0.8902 ✓ | 0.7957 ✓ | 0.9798 ✓ |
| **兩個都改** | **0.9117** ✓ | **0.8119** ✓ | **0.9836** ✓ |

**兩個錯誤方向相反**（FM 太小、回授太大），所以單獨看任一個都不像「差很多」，
合起來才把中段拖垮——這也是為什麼前 15 秒（清一色回授 7 ＋ 快起音）看起來還好。

## 2. 判準為什麼改（`docs/spec/016` §2）

`docs/re/007` 的方法是**從複音音訊反推單音的起音與音高**再對樂譜，方法誤差比要量的差異還大——
當時 dosgolem 的 WAV 對自己的樂譜都不通過。

現在事件層已經與 DOSBox-X 逐筆相同，音高與節奏由事件決定，所以只剩一個問題：
**同一串暫存器寫入，兩個合成器算出來的波形有多接近。** 這是兩份訊號的比較，不需要音樂資訊抽取。

門檻由對照定出來，不是憑感覺挑的：上界是 DOSBox-X 同一段錄兩次（0.9972／0.9787／0.9992），
下界取「同音色不同內容」與「同曲不同音源」中較嚴的那個，門檻 ＝ `L + 0.7 × (U − L)`。

## 3. 排除了什麼（一次只改一個變因）

`internal/opl2` 加了診斷開關（`Feature`／`RenderWithout`，probe 的 `-opl-disable`），
一次關掉一個功能各合成一次整曲：

| 關掉 | `spec` | `env` | `chroma` | 讀法 |
|---|---:|---:|---:|---|
| （全開） | 0.8086 | 0.7007 | 0.9730 | 基準 |
| KSL | 0.7924 | **0.7579** | 0.9708 | KSL 讓 `env` 掉 0.057、`spec` 升 0.016 |
| 震音 | 0.8081 | 0.7007 | 0.9730 | 影響 < 0.001 |
| 顫音 | 0.8086 | 0.7007 | 0.9730 | 完全沒差 |
| 指數起音 | 0.8125 | 0.7038 | 0.9734 | 回到線性起音反而略好 |

其他排除的假設：

| 假設 | 怎麼否掉 |
|---|---|
| 時間軸速度差（兩邊播放速度不同） | `chroma` 全程 0.956 以上；分段位移不是單調漂移，是在 15–35 秒亂跳 |
| 段落之間的間隔不同 | 事件序列最大的間隙在 54.7 秒與 74.4 秒，15 秒附近沒有 |
| 混音截幅 | 全曲觸頂樣本 0.000%，峰值最高 18,612（滿刻度 32,767） |
| KSL 造成中段崩掉 | 關掉 KSL 後中段的相關幾乎沒變（0.198 vs 0.178） |
| 起音形狀造成中段崩掉 | 回到線性起音後中段幾乎沒變（0.614 vs 0.601） |

**前段清一色是回授 7 ＋ 快起音，而那一段我們合成得很像（`spec` 0.95）。**
中段換成回授 5 ＋ 慢起音之後就不像了，但單獨關掉起音或 KSL 都救不回來——
所以問題不是某一個功能開關，而是那些參數組合下的波形算法本身。

## 5. 逐聲道：沒有「壞掉的那一個」

合成器加了兩個診斷開關（dosgolem `196` §3.3）：`-opl-only <c>` 只混那一個聲道、
`-opl-except <c>` 把那一個排除。**後者才是能用的比較**——參照（DOSBox-X）那邊是混音、拆不開，
「只留一個聲道」沒得比；「拿掉某一個之後保真度反而上升」才指得出拖累。

標題曲前 30 秒，逐一排除（對照：全開 `spec` 0.8086、`env` 0.7007、`chroma` 0.9730）：

| 排除 | `spec` | `env` | `chroma` |
|---|---:|---:|---:|
| 聲道 0 | 0.7365 | 0.6803 | 0.9673 |
| 聲道 1 | 0.7653 | 0.6813 | 0.9676 |
| 聲道 2 | 0.7670 | 0.6841 | 0.9664 |
| 聲道 3 | 0.7819 | 0.6514 | 0.9667 |
| 聲道 4 | 0.7726 | **0.7043** | 0.9682 |
| 聲道 5 | 0.7661 | 0.6808 | 0.9676 |
| 聲道 6 | 0.7767 | 0.6944 | 0.9675 |
| 聲道 7 | 0.7571 | 0.6727 | 0.9672 |
| 聲道 8 | 0.7623 | 0.6916 | 0.9679 |

**九個聲道拿掉任何一個，`spec` 都下降**（0.8086 → 0.74–0.78），`chroma` 也都下降。
唯一的例外是聲道 4 的 `env` 升了 0.004——這個幅度比量測本身的抖動還小，不構成證據。

結論：**沒有「壞掉的那一個聲道」。** 每個聲道各自都在把結果往參照那邊拉，
偏差是**全體性**的——所有聲道共用的那幾件事（包絡速率、回授尺度、混音）裡有系統性的差。

這一步的價值在於**排除了一整類假設**。原本合理的想法是「某個聲道用了我們做不好的音色」，
逐聲道之後這條路封掉了，剩下的方向少很多。

## 6. 怎麼找到的：相位單位

逐聲道排除了「某個聲道壞掉」之後，剩下的方向是「所有聲道共用的東西」。
回去讀真機的資料流（DOSBox-X 的 `dbopl`，**只確認語意不照抄數值**）：

```
index = ForwardWave() + modulation;   // 相位是波表索引
return GetWave(index, vol);
WaveForm0: wave = SinTable[i & 511]; neg = (i >> 9) & 1;   // 一個週期 = 1024 個索引
mod = (old[0] + old[1]) >> feedback;   // feedback = 9 - FB
```

關鍵是 `i & 511` 取正弦表、`(i >> 9) & 1` 決定正負半週——**一個完整週期是 1024 個索引，不是 512**。
運算子滿幅輸出約 ±4085，於是：

| | 真機 | 第一版 | 差 |
|---|---|---|---|
| FM 調變量 | 4085 ÷ 1024 ≈ 4 週期 ＝ `8π` | `4π` | 少一半 |
| 回授（FB ＝ 7） | `(old₀+old₁) >> 2` ≈ 2 週期 ＝ `4π` | `8π`（`2^(FB−4)`） | 多一倍 |

**兩個錯誤方向相反**，所以整體聽起來不是「調變太淺」也不是「太深」，而是某些參數組合下才明顯——
前 15 秒清一色回授 7 ＋ 快起音，兩個誤差剛好互相抵消掉一部分，看起來還好；
中段換成回授 5 ＋ 慢起音之後就露餡。

教訓：**這種「比例對、基準錯」的問題，逐項開關測不出來**（`docs/re/032` §3 關掉 KSL、震音、顫音、
指數起音都沒改善），因為它不是某個功能壞掉，而是所有人共用的座標軸歪了。
要回到規格的第一性——真機的單位是什麼。
