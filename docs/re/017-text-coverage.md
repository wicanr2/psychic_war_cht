- 載入位置來自 probe `-reads-of .BIN` 的讀檔紀錄（「要 5000 得 N（線性 起–迄）」），載入順序來自同一份紀錄的步數。

- 地點名稱原本不在清單裡：覆蓋率第一次跑時，腳本緩衝區 `16816` 印出含自訂字模的字串（`{8E}{9E}{91}{A1}{B1}`），以位元組序列搜尋原版檔案，只出現在 `I_MAPnn.BIN` 偏移 200h 起的名稱表，補進規格 `007` §3.5。

## 4. 方法

1. `tools/text_coverage.sh`：`tools/states.sh --check` 重跑重播（畫面雜湊全部相同，確認加紀錄沒有改變執行），每段加：
   - `-reads-of .BIN`（讀檔事件）
   - `-regs-at 0161:6289,0161:62A2,0161:62AF`（`FONT.BIN` 三支字串迴圈，每字一筆）
   - `-call-args 0161:B0F1 … -arg-regs`（小字型每字一筆，含返回位址與 BX、DX）
2. `tools/text_coverage.py`：依 `docs/spec/007` §6.2 換算。載入表沿重播檔的 `from` 串接。

## 5. 限制與重開條件

- 路線涵蓋率低（§1）。重播推進到新區域、結局、開場故事（標題畫面等待）時，重跑 `tools/text_coverage.sh` 看第四個數字。
- 地點名稱從 `I_MAP` 複製到緩衝區的程式碼沒有讀，歸屬靠內容比對；兩個地點同名時分不出是哪一筆（不影響譯文，同名同譯）。
- 敵人名稱同樣靠內容比對最近載入的 `I_ENMY`。
- 圖檔內嵌文字（`.PBL`，#18）不在這些數字裡；標題畫面兩套字型都沒有使用，推定是圖。
