# 014：印字常式

狀態：量測紀錄（2026-09-17）。對應 issue #15。位址：IDA ＝ `PW_UNP.EXE` 線性位址；執行期 CS ＝ `0161`（`IDA ＝ 10510h ＋ 偏移`），DS ＝ `1175`。

## 1. 結論

遊戲自己畫字，不經過 BIOS。從上到下四層：

| 層 | 位址（IDA／執行期） | 輸入 | 做什麼 | 證據 |
|---|---|---|---|---|
| 字串：固定長度 | `sub_16799`／`0161:6289` | `ds:[BX]` 起 CH 個字元 | 逐字呼叫單字元輸出。I_MENU 訊息以 CH ＝ 10h 一行一行印 | 動態：撞牆訊息時 BX ＝ `27F6`、CH ＝ 10h，指到 `I_MENUH` 偏移 530h |
| 字串：到 0 為止 | `sub_167B2`／`0161:62A2` | `ds:[BX]` | 同上，遇 0 停（實跑：狀態欄數字、方位名稱） | 靜態＋實跑 |
| 字串：程式內嵌 | `sub_167BF`／`0161:62AF` | `cs:[BX]` | 同上，字串在程式碼段（實跑：戰鬥中的敵人名稱、投降訊息；`ENTER YOUR NAME:` 不走這支，§4） | 靜態＋實跑 |
| 單字元 | `sub_16629`／`0161:6119` | AL | ≥ 20h 畫字模並前進；10h–17h、18h–1Fh 設兩個顏色值；< 10h 查 `cs:61F3` 跳躍表當控制碼 | 靜態 |
| 字模 | `sub_1884B` 依顯示模式分派，EGA 是 `loc_17205`／`0161:6CF5` | AL | 字模 ＝ `[ds:word_2B52C] ＋ (AL − 20h) × 8`，8×8，逐平面寫 A000 | 動態：`-vram-sites` 定位到同一片段 |

- **字模來源是 `FONT.BIN`**：2,048 bytes ＝ 256 個 8×8 字模，從字碼 20h 開始。載入在 `ds:42C6`（線性 `0x15A16`），記憶體傾印與原檔相同的片段找到。
  80h 以上的字碼是自訂字模（地名、特殊符號），I_MENU 文字裡直接使用（例：`{95}{A5}{B5}{C5}{D5}{96}{A6}`）。
- **游標** `cs:word_1661E`（線性 `0x771E`）：低位元組 Y、高位元組 X，單位都是 4 像素；每字 X ＋2（8 像素），X ≥ 4Fh 換行（`sub_166CF`）。
- **顏色** `cs:word_1661A`：低位元組、高位元組分別由 10h–17h、18h–1Fh 設定；高位元組當 EGA 平面遮罩寫進 3C5h。
- **訊息框**：`sub_16770` 先呼叫 4 次捲動（`sub_187D9` → VRAM 區塊複製 `sub_170A1`，每次上移 2 列像素），再把游標設到第 1Ch 列、第 2 欄，然後印字。
  所以「一則訊息的像素」會被後續捲動搬動；比對畫面時要在印完、下一則捲動前取樣。
- **I_MENUH 載入在 `ds:22C6`**（線性 `0x13A16`），記憶體內容與原檔逐位元組相同。I_MENUnn 推定載入在同一區（換區域時換檔，`docs/re/011`）。

## 2. 怎麼找到的

1. 從 `07-first-play` 以 750 cycles 往東撞牆，出現「You can't move forward here.」；比對前後畫面，文字在 x 8–118、y 105–119。
2. `-vram-sites -vram-at 1109`（第 109 列、第 8 像素）→ 寫入點 `0161:6BCD` 等四條，是 `sub_170A1`（VRAM 區塊複製）。
   `-regs-at 0161:6BCD` 顯示 BX ＝ `0DC1` → DX ＝ `0E11`，差 80 bytes ＝ 2 列：這是捲動，不是畫字。
3. `-vram-sites`（不限位移）列出同一段時間所有寫 VRAM 的指令，排除捲動後剩 `0161:6D69` 起兩組各 189 次，在 `sub_1884B` 分派的 `loc_17205`。
4. `refs:1884B` → 唯一的 call 在 `sub_16629`（單字元輸出）；`refs:16629` → 9 個呼叫點，其中三支是字串迴圈（§1）。
5. `-regs-at 0161:6289,0161:62A2,0161:62AF`：撞牆訊息只經過 `sub_16799`。

⚠ `tools/ida/dump.py` 的 `func:`／`dis:` 對 `sub_1884B` 附近與 `16600` 一帶會讓 idat 異常結束（輸出 0 bytes），這兩段是從 `workplace/ida/PW_UNP.EXE.asm` 讀的。

## 3. 攔截點候選

| 候選 | 拿得到 | 限制 |
|---|---|---|
| 字串層 `0161:6289`／`62A2`／`62AF` | 一整行文字與來源指標（可以反推檔案與偏移 → 文本 key） | I_MENU 訊息一行 16 字元分開印，要把同一則的兩行合回一則；實跑只涵蓋約 25% 的字元（§4） |
| 單字元 `0161:6119` | 每個字元、游標、顏色，涵蓋所有路徑 | 失去「一則訊息」的邊界與來源；控制碼混在字元流 |
| 字模 `0161:6CF5` | 畫面位置最精確 | 只有 EGA 模式；太低層，只適合畫布座標對齊 |
| 訊息框 `sub_16770` | 一則訊息的開始（捲動 4 次） | 只涵蓋訊息框，不含選單與固定畫面文字 |

建議：**字串層攔截取得來源與文字、單字元層確認涵蓋率**（字串層漏掉的字元 ＝ 還有別的印字路徑）。

## 4. 實跑量測（`tools/print_trace.py`）

在重播 18 段上，於三支字串函式與單字元輸出的進入點記暫存器，並在呼叫當下傾印指到的記憶體：

| 指標 | 值 |
|---|---:|
| 三支字串函式的呼叫（合併逐字元命中後） | 1,585 次：`sub_167B2` 1,291、`sub_167BF` 217、`sub_16799` 77 |
| 不重複字串 | 62 |
| 單字元輸出畫出的字元（AL ≥ 20h） | 25,843 |
| 其中經由三支字串函式（估計） | 6,505（約 25%） |

- **這三支不是全部的印字路徑**：標題與防拷畫面的文字（`MATCH THE ALLY…`）、`ENTER YOUR NAME:` 都沒有出現在字串函式的紀錄裡，
  約 75% 的字元來自其他呼叫單字元輸出的地方（`refs:16629` 的其餘 6 個呼叫點）。攔截要以單字元層為最終涵蓋率基準。
- 字串函式的三個位址都是**迴圈頭**：每印一個字元命中一次。「同一常式、位址連續加 1」併成一個字串；
  `sub_16799` 另外要 CH 剛好少 1，否則訊息的第二行（位址緊接第一行）會被併成同一行。
- 各常式印的內容：`sub_16799` ＝ I_MENU 訊息與選單（逐行）；`sub_167B2` ＝ 數字與方位名稱（狀態欄）；
  `sub_167BF` ＝ 戰鬥中的敵人名稱與投降訊息（`{18}{15}I..I Surrender!{17}`）。
- 同一段內同一位址只在第一次呼叫時傾印（戰鬥中數字重印上千次）；數字字串因此只代表第一次的值。

## 5. 限制與重開條件

- CGA（模式 1）、模式 5／6 的字模分派未讀。
- 控制碼跳躍表 `cs:61F3` 各項未讀。
- 單字元輸出其餘 6 個呼叫點（標題、防拷、輸入名字等）未讀。
