# 014：印字常式

狀態：量測紀錄（2026-09-17）。對應 issue #15、#19。位址：IDA ＝ `PW_UNP.EXE` 線性位址；執行期 CS ＝ `0161`（`IDA ＝ 10510h ＋ 偏移`），DS ＝ `1175`。

## 1. 結論

遊戲自己畫字，不經過 BIOS，而且有**兩套字型**：遊戲中的介面用 `FONT.BIN`（8×8，下表），開機、防拷、選單、輸入名字、故事與製作群用程式內建的小字型（6×6，§5）。
`FONT.BIN` 這一套從上到下四層：

| 層 | 位址（IDA／執行期） | 輸入 | 做什麼 | 證據 |
|---|---|---|---|---|
| 字串：固定長度 | `sub_16799`／`0161:6289` | `ds:[BX]` 起 CH 個字元 | 逐字呼叫單字元輸出。I_MENU 訊息以 CH ＝ 10h 一行一行印 | 動態：撞牆訊息時 BX ＝ `27F6`、CH ＝ 10h，指到 `I_MENUH` 偏移 530h |
| 字串：到 0 為止 | `sub_167B2`／`0161:62A2` | `ds:[BX]` | 同上，遇 0 停（實跑：狀態欄數字、方位名稱） | 靜態＋實跑 |
| 字串：程式內嵌 | `sub_167BF`／`0161:62AF` | `cs:[BX]` | 同上，字串在程式碼段（實跑：戰鬥中的敵人名稱）。`cs:6294` 是它的包裝：把返回位址當字串指標，字串緊接在 `call` 之後（投降訊息，§7） | 靜態＋實跑 |
| 單字元 | `sub_16629`／`0161:6119` | AL | ≥ 20h 畫字模並前進；10h–17h、18h–1Fh 設兩個顏色值；< 10h 查 `cs:61F3` 跳躍表當控制碼（§6） | 靜態 |
| 字模 | `sub_1884B` 依顯示模式分派，EGA 是 `loc_17205`／`0161:6CF5` | AL | 字模 ＝ `[ds:word_2B52C] ＋ (AL − 20h) × 8`，8×8，逐平面寫 A000 | 動態：`-vram-sites` 定位到同一片段；存檔那段實跑對 `FONT.BIN` 的 6,648 次讀取**全部**來自 `0161:7007` |

- **字模來源是 `FONT.BIN`**：2,048 bytes ＝ 256 個 8×8 字模，從字碼 20h 開始。載入在 `ds:42C6`（線性 `0x15A16`），記憶體傾印與原檔相同的片段找到。
  80h 以上的字碼是自訂字模（地名、特殊符號），I_MENU 文字裡直接使用（例：`{95}{A5}{B5}{C5}{D5}{96}{A6}`）。
- **游標** `cs:610E`（IDA `word_1661E`，線性 `0x771E`）：低位元組 Y、高位元組 X，單位都是 4 像素；每字 X ＋2（8 像素），X ≥ 4Fh 換行（`sub_166CF`）。
- **顏色** `cs:610A`（IDA `word_1661A`，線性 `0x771A`）：低位元組、高位元組分別由 10h–17h、18h–1Fh 設定。撞牆訊息實測值 0003h，畫出來前景色號 11、背景 0；色號由 `loc_17205` 依 EGA 寫入模式算出，換算規則未讀。
- **訊息框**：`sub_16770` 先呼叫 4 次捲動（`sub_187D9` → VRAM 區塊複製 `sub_170A1`，每次上移 2 列像素），再把游標設到第 1Ch 列、第 2 欄，然後印字。
  所以「一則訊息的像素」會被後續捲動搬動；比對畫面時要在印完、下一則捲動前取樣。
- **I_MENUH 載入在 `ds:22C6`**（線性 `0x13A16`），記憶體內容與原檔逐位元組相同。I_MENUnn 推定載入在同一區（換區域時換檔，`docs/re/011`）。

## 2. 怎麼找到的

1. 從 `07-first-play` 以 750 cycles 往東撞牆，出現「You can't move forward here.」；比對前後畫面，文字在 x 8–118、y 105–119。
2. `-vram-sites -vram-at 1109`（第 109 列、第 8 像素）→ 寫入點 `0161:6BCD` 等四條，是 `sub_170A1`（VRAM 區塊複製）。
   `-regs-at 0161:6BCD` 顯示 BX ＝ `0DC1` → DX ＝ `0E11`，差 80 bytes ＝ 2 列：這是捲動，不是畫字。
3. `-vram-sites`（不限位移）列出同一段時間所有寫 VRAM 的指令，排除捲動後剩 `0161:6D69` 起兩組各 189 次，在 `sub_1884B` 分派的 `loc_17205`。
4. `refs:1884B` → 唯一的 call 在 `sub_16629`（單字元輸出）；`refs:16629` → IDA 認得 9 個呼叫點，其中三支是字串迴圈（§1）；IDA 沒有標成程式碼的地方還有，位元組掃描 `E8` 共 32 個（§4）。
5. `-regs-at 0161:6289,0161:62A2,0161:62AF`：撞牆訊息只經過 `sub_16799`。

⚠ `tools/ida/dump.py` 的 `func:`／`dis:` 對 `sub_1884B` 附近與 `16600` 一帶會讓 idat 異常結束（輸出 0 bytes），這兩段是從 `workplace/ida/PW_UNP.EXE.asm` 讀的。

## 3. 攔截點候選

| 候選 | 拿得到 | 限制 |
|---|---|---|
| `FONT.BIN` 字串層 `0161:6289`／`62A2`／`62AF` | 一整行文字與來源指標（可以反推檔案與偏移 → 文本 key） | I_MENU 訊息一行 16 字元分開印，要把同一則的兩行合回一則；三支都是迴圈頭，每字命中一次 |
| `FONT.BIN` 單字元 `0161:6119` | 每個字元、游標、顏色 | 失去訊息邊界與來源；混著游標閃爍（FEh／FFh）、箭頭（7Fh）、補空白 |
| 小字型區塊 `0161:B016`（60 bytes）、`B058`（20 bytes） | 一整塊文字與 `cs` 來源位址 | 只涵蓋選單、防拷、輸入框；故事與製作群走各自的迴圈（§5） |
| 小字型單字元 `0161:B0F1` | 每個字元與像素座標（SI、DI） | 同一個字元畫 6 列 × 3 次繪點呼叫，不能在更底層攔 |
| 字模 `0161:6CF5` | 畫面位置最精確 | 只有 EGA 模式；太低層，只適合畫布座標對齊 |

建議：**兩套字型各在字串層攔截取得來源與文字，單字元層當涵蓋率基準**（§4、§5 的歸類表就是基準）。

## 4. `FONT.BIN` 路徑的實跑量測（`tools/char_callers.py`）

在重播 18 段上，於 `0161:6119` 以 `-call-args 0161:6119:1:0:<大數> -arg-regs` 記錄每一次呼叫的返回位址（近呼叫 ＝ 呼叫端）與 AL：

| 呼叫端（返回位址） | 字元數 | 字碼 | 是什麼 |
|---|---:|---|---|
| `0161:600F`（`sub_164F7`） | 18,403 | 只有 FEh、FFh | 等待按鍵時的游標閃爍字模 |
| `0161:62AD`（`sub_167B2` 迴圈） | 5,025 | 37 種 | 狀態欄數字、方位名稱 |
| `0161:628E`（`sub_16799` 迴圈） | 963 | 55 種 | `I_MENU` 訊息與選單 |
| `0161:5CBC`、`5CB5`、`5C78`、`5C23` | 798 | 只有 20h | 選單與檔案清單補空白 |
| `0161:62BB`（`sub_167BF` 迴圈） | 524 | 20 種 | 程式內嵌字串（敵人名稱） |
| `0161:6041`（`sub_16534`） | 112 | 只有 20h | 擦掉游標 |
| `0161:5B4E` | 18 | 只有 7Fh | 選單箭頭 |
| **合計** | **25,843** | | 文字 6,512（三支字串函式）；非文字 19,331；**歸不到呼叫端 0** |

- 路線上沒有出現控制碼（AL < 10h）。
- 位元組掃描 `E8` 呼叫目標，`0161:6119` 共 32 個呼叫點。路線沒觸發的 22 個都讀過：顏色碼（`17h`、`18h`、訊息類型位元組的高 4 位元當顏色）、控制碼 08h／0Ch 的處理（§6）、
  腳本指令「印一個字元」（`0161:2792`，字元來自 `CODE` 位元組碼，§7）、`FONT.BIN` 的行輸入回顯（`0161:5E76`，緩衝區 `[ds:AEE4]`）。
- 字串函式的三個位址都是**迴圈頭**：每印一個字元命中一次。「同一常式、位址連續加 1」併成一個字串；
  `sub_16799` 另外要 CH 剛好少 1，否則訊息的第二行（位址緊接第一行）會被併成同一行（`tools/print_trace.py`）。

## 5. 第二套字型：程式內建的小字型

- **單字元** `sub_1B601`／`0161:B0F1`：AL ＝ 字碼，SI／DI ＝ 像素 X／Y，AH ＝ 顏色。字模指標表在 `cs:B13D`（字碼 20h 起，每項 2 bytes），字模資料 `cs:B1FD–B3B9`（執行期線性 `C80D–C9C9`）：
  每字 6 bytes ＝ 6 列，每列取高 6 位元、兩位元一組，對應 3 個 2 像素寬的點，交給繪圖原語 `sub_1AC89`。所以一個字是 6×6 像素，字距 6、行距 7。
- 存檔那段實跑對小字型字模的 512 次讀取全部來自 `sub_1B601` 內的 `0161:B104`、`B10C`。
- 呼叫點（位元組掃描 `E8`，共 8 個）與實跑：

  | 呼叫點 | 印什麼 | 字串格式 | 重播 18 段實跑 |
  |---|---|---|---:|
  | `0161:B027`（`sub_1B526`／`B016`） | 選單、防拷、輸入框、訊息框 | `cs:BX` 起 **60 bytes 固定**（3 行 × 20），畫在 (100, 89) | 540 |
  | `0161:B052`（`B03C`） | 單格字元：輸入回顯、選擇游標 `>` | AL，第 CH 欄、第 CL 列 | 295 |
  | `0161:6537`、`654B`（`0161:6504`） | 防拷題目的盟友名與基地名 | `cs:66F7` 盟友 11 × 8 bytes、`cs:674F` 基地 7 × 8 bytes | 16 |
  | `0161:079D`（`0161:0788`） | 開場故事 | `cs:BX` 起 160 bytes（8 行 × 20），3 頁：`0287`、`0327`、`03C7` | 0 |
  | `0161:07CE`（`0161:07C1`） | 版權行 | `cs:BX` 到 00：`0467`、`0495` | 0 |
  | `0161:0BAE`、`1256`（`0BA3`、`124B`） | 製作群 | `cs:0BD7` 起 47 行 × 20 bytes | 0 |

  **歸不到呼叫端 0**（851 字）。開場故事、版權、製作群在這條重播路線上沒有觸發；從 `01-title` 不按鍵、以 750 cycles 跑 7 億道指令也沒有出現（進入條件未讀）。
- `B016` 的呼叫者與區塊位址：`65E5`（配對說明）、`6621`（ESP 錯誤）、`656D`（輸入 ESP）、`65A9`（沒收 Kayla）、`665D`／`6699`（通過，二選一）、`89B3`（SELECT）、`8A4D`（輸入檔名）、`8AEF`（輸入名字）、`B07D`（按任意鍵，第 1 行由 `B058` 從 20 bytes 行複製進來：`8851`、`88A8`、`88D1`、`88FA`、`8923`）。
- 標題畫面兩套字型都沒有用到（`01-title` 兩種紀錄都是 0 字），推定是 `OPEN.PBL` 圖檔（#18）。

## 6. 控制碼（`FONT.BIN` 路徑，`cs:61F3` 跳躍表）

游標 `cs:610E` 的單位是半格（X 每字 ＋2）。處理完都回到 `cs:6153`（彈回暫存器）。靜態讀 bytes，路線上未觸發：

| 碼 | 位址 | 動作 |
|---|---|---|
| 00h、07h、0Eh、0Fh | `6213` | 無動作（`retn`） |
| 01h | `6162` | 前進一格（X ＋2，≥ 4Fh 換行） |
| 02h | `617F` | 後退一格（X −2，跨行時回到上一行行尾） |
| 03h | `6199` | 上移一行（Y −2，越界繞到底） |
| 04h | `61C2` | 下移一行（Y ＋2，≥ 31h 繞回） |
| 05h | `6176` | 前進半格（X ＋1） |
| 06h | `61B6` | 下移半行（Y ＋1） |
| 08h | `6214` | 退格：後退、印空白、再後退 |
| 09h | `61AA` | Tab：前進到 X 為 16 的倍數 |
| 0Ah | `61BF` | 換行：回行首再下移一行 |
| 0Bh | `6220` | 游標回原點（X、Y 只留最低位元） |
| 0Ch | `6235` | 回原點後以空白填滿整個畫面範圍 |
| 0Dh | `61D3` | 回行首（X 只留最低位元） |

## 7. 程式內嵌字串清單（`PW_UNP.EXE`，`FONT.BIN` 路徑）

- `sub_167BF`（`cs:BX` 到 00）：結局與遊戲結束文字 `08D7`、`0901`、`092B`、`0955`、`097F`、`0A40`、`0A6A`、`0A94`（各 40 字，前綴顏色碼 17h）；`3A4C` 是戰鬥時從 `I_ENMY` 複製進來的敵人名稱（不是固定文字）。
- `cs:6294` 內嵌呼叫：`4AC0`「We are exposed!」、`4AF8` 投降訊息，另有 3 則只有顏色碼或空白（`2EE0`、`2F3C`、`3E17`）。
- `sub_167B2`（`ds:BX` 到 00）的 10 個呼叫點都是執行期緩衝區（`[ds:AEE4]` 等：數字、方位、玩家名字），來源是 `CODE` 腳本與遊戲狀態，不是固定文字。
- `sub_16799`（`ds:BX` 定長）：`6285` 印 `I_MENU` 訊息；`2808` 是腳本指令；`5CD2`、`5CFE` 印存檔清單的檔名（玩家資料）。

## 8. 限制與重開條件

- CGA（模式 1）、模式 5／6 的字模分派未讀。
- 控制碼（§6）只有靜態讀 bytes，路線上沒有觸發。
- 開場故事、版權、製作群、結局文字在重播路線上沒觸發，歸類靠靜態；重播加上「標題等待」與結局後要補實跑。
- 「每個字元都歸到來源」只在重播 18 段成立；兩份字模表的讀取者只在存檔那一段監看過。
