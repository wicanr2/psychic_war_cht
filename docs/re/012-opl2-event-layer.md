# 012：OPL2 事件層比對（dosgolem vs DOSBox-X raw OPL）

狀態：量測紀錄（2026-09-17）。對應 issue #5。方法見 `docs/spec/005`。

## 1. 結論

- **遊戲的 AdLib 驅動在 dosgolem 上寫進 OPL2 的暫存器序列，與 DOSBox-X 逐筆相同**：
  從第一個音起 5,599 筆（標題曲全曲 4,577 筆＋防拷畫面一段 187 筆＋迷宮音樂前 835 筆）完全一致。
- 判定：
  - **原判準（spec 005 §4）：不通過**。DOSBox-X 擷取 5,615 筆，最後 16 筆與 dosgolem 不同。
  - **修訂判準（§4.1，看過結果後加）：通過**。那 16 筆是迷宮中按 Ctrl+Q 結束遊戲時，2 ms 內把 9 個聲道的 A0–A8、B0–B8 全寫 0；
    dosgolem 端沒有結束遊戲。擷取要靠遊戲正常結束才寫標頭，這段結尾是量測程序本身帶進來的。
- 這一層證明「驅動照原樣寫暫存器」；WAV 層（`docs/re/007`）不通過的原因在合成器與比對方法，不在驅動或 CPU 模擬。

## 2. 輸入

| 來源 | 指令 | 產出 |
|---|---|---|
| DOSBox-X | `tools/dosboxx-opl.sh 90` | `pw_000.dro`：7,712 個命令、117,857 ms；過濾延遲命令後 5,615 筆寫入 |
| dosgolem | `probe -adlib -steps 1900000000 -press space,enter,enter,space,enter,25,1E,17,enter -press-at 1060063425 -press-every 30000000 -opl-log …` | 全部寫入；照 spec 005 §3 過濾後 7,184 筆 |

DOSBox-X 流程：`DX-CAPTURE /O /-D PW.EXE`，標題等 90 秒，看畫面變化送鍵走進迷宮，Ctrl+Q，GAME OVER 畫面再按一鍵回 DOS。
dosgolem 的第一個按鍵時點由 DRO 換算：標題曲第一筆在第 7,224,583 步、DRO 第 90,900 ms 出現按鍵後的第一筆，
以標題曲段的時間斜率換算成第 1,060,063,425 步。之後每個鍵間隔 3,000 萬步（約 2.6 秒），讓每段音樂在換畫面前播完。

## 3. 結果

`tools/py.sh tools/opl_events.py workplace/audio/opl-title-to-maze.txt workplace/dosboxx-opl/capture/pw_000.dro`

| 項目 | 值 |
|---|---:|
| dosgolem 過濾後筆數 | 7,184 |
| DOSBox-X 筆數 | 5,615 |
| 原判準：比較筆數／一致前綴 | 5,615／5,599 |
| 結尾全聲道靜音筆數 | 16 |
| 修訂判準：比較筆數／一致前綴 | 5,599／5,599 |
| 時間診斷：只比標題曲時的斜率 | 每百萬步 86.338 ms（＝每秒 11.58 M 步，與 dosgolem 預設速度一致） |

DRO 時間軸：標題曲 0–73.3 秒；停 17.6 秒後按鍵，防拷畫面一段 187 筆（90.9–94.1 秒）；停 6.1 秒後迷宮音樂 100.2 秒起，到 Ctrl+Q 為止。

反向對照：把 dosgolem 過濾後第 3,000 筆（只有標題曲時）與第 5,000 筆的值改掉，工具分別回報一致前綴 3,000 與 5,000，兩種判定都不通過。

## 4. 走過的彎路（都已修進工具的註解）

- 這版 DOSBox-X 的指令是 `DX-CAPTURE`（有連字號），寫成 `DXCAPTURE` 會回 Bad command。
- 直接關掉 DOSBox-X 時標頭不會寫（指令數 0）。標題畫面按 Ctrl+Q 只當一般按鍵；要進迷宮才能結束，而且 GAME OVER 畫面還要再按一鍵。
- DRO 擷取有自己的過濾（值沒變不記、計時器暫存器不記、開頭寫快取），dosgolem 端要照做才能逐筆比。

## 5. 限制

- 只比了標題、防拷、迷宮開頭三段音樂；戰鬥音樂與其他區域未比。
- 時間只做診斷，沒有逐筆比時間。
