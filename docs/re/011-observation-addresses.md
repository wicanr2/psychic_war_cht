# 011：觀測位址（位置、朝向、地點、角色數值）與地圖檔格式

狀態：量測紀錄（2026-09-17）。對應 issue #8（全程重播）、#33（作弊）、#32（地圖）。

## 1. 結論

遊戲邏輯跑在一台位元組碼直譯器上（`sub_12766` 依 opcode 分派，IDA 12766 起）。
腳本變數是字組陣列，基底由 `word [ds:2B536h]` 指到（執行期 DS ＝ `1175h`，值 `51C6h`，基底線性 `0x16916`）；
變數 n 在 `0x16916 ＋ 2n`。下表位址都是**線性**位址（probe `lin:`）。

| 位址 | 變數 | 內容 | 驗證 | 等級 |
|---|---:|---|---|---|
| `0x16966` | 40 | 區域編號：0 Samar、1 Sivad（對應 `I_MAPnn`） | 在 Samar 改成 1／2 後進出發平台：訊息變成「Watch it. Enemy territory!」，目的地清單的 Sivad 換成 Samar（清單排除目前所在站）；對照組是「You're on space station Samar」。實際搭乘到 Sivad 時由 0 變 1，同時開 `I_MAP01`、`CODE1`、`I_MENU01`、`ENEMY01`、`I_ENMY01` | 強 |
| `0x16968` | 41 | 地圖 X（往西減 1） | 改成 2／3／5 後前進：分別進 Radar Room、BBS Room、另一段走廊，畫面雜湊各不同 | 強 |
| `0x1696A` | 42 | 地圖 Y（往北減 1） | 改成 0E／0A／06／04／02 後前進：五種畫面雜湊都不同 | 強 |
| `0x1696C` | 43 | 另一組 X，與 X 同步（Samar 是 X ＋ 6，Sivad 抵達時是 X ＋ 3） | 改值後前進，畫面與地點都不變 | 用途未明 |
| `0x1696E` | 44 | 另一組 Y，與 Y 同步（Samar 是 Y ＋ 2，Sivad 抵達時是 Y ＋ 5） | 同上 | 用途未明 |
| `0x16970` | 45 | 朝向：0 北、1 東、2 南、3 西 | 改成 2（南）後轉身，畫面顯示朝北；對照組朝南 | 強 |
| `0x16976` | 48 | 前方可否通行：00 可走、02 不可（轉向或移動後重算） | 正常遊玩在 (1,8) 右轉面東時寫 02，之後 6 次前進都沒動；再右轉面南寫 00，前進成功。只改座標不會重算，傳送後前進沿用舊值（§3.4） | 中 |
| `0x16978` | 49 | 地點編號（`I_MAP` 地點格的值；20 ＝ 走廊） | 移動時與地圖檔的地點格一致（§3）；直接改值不會重畫 PLACE 欄 | 中 |
| `0x1698E` | 60 | 玩家 HP 上限 | 與 HP、名字排在同一筆紀錄 | 中 |
| `0x16990` | 61 | 玩家 HP | 遭遇時改成 3：畫面顯示 3，之後陣亡回到輸入名字；戰鬥中唯一寫入點 `0161:44DF`（敵人攻擊 `sub_1492E`） | 強 |
| `0x16992` | 62 | 能量上限 | 同 `0x1698E` | 中 |
| `0x16994` | 63 | 能量 | 遭遇時改成 0：右上角能量顯示 0 | 強 |
| `0x1699A` | — | 主角名字（8 字元，空白補齊） | 讀到輸入的 `kai` | 強 |
| `0x509C` | — | 敵人 HP（`0161:3A8C`，玩家攻擊 `sub_14A31` 寫入） | `docs/re/009` §3 | 強 |
| `0x509E` | — | 能量的戰鬥用副本（推定；`0161:3A8E`） | 遭遇時改成 0：能量顯示 0 | 強（行為）／推定（角色） |

- 同一份資料在戰鬥與迷宮中的位址相同（戰鬥傾印與迷宮傾印都在 `0x1698E` 找到同一筆紀錄）。
- 區域編號在搭乘出發平台換站時找到：換站前後傾印中 00 → 01 的位元組有 52 個，落在變數表裡的只有變數 40、306、346、416，其中變數 40 緊鄰 X 座標，改值驗證通過。

⚠ probe 的 `-dump-mem-at` 位址不加 `lin:` 時會當成 IDA 位址（減 `0xEF00`），整份傾印錯開 `0xEF00`，而且看起來像正常的記憶體。

## 3. 地圖檔 `I_MAPnn.BIN`（1,024 bytes）

### 3.1 版面

| 偏移 | 大小 | 內容 | 等級 |
|---|---:|---|---|
| `0x000` | 256 | 16×16 牆壁格（每格 1 byte，列優先：`y × 16 ＋ x`） | 推定（位元意義未解） |
| `0x100` | 256 | 16×16 地點格，值同 `0x16978` | 強（§3.2） |
| `0x200` | 512 | 地點名稱表，8 bytes 一筆，含自訂字碼；編號 24–27 的名稱是 `Elevator` | 推定 |

### 3.2 地點格的值（`I_MAP00`，Samar）

以 `0x16968`／`0x1696A`／`0x16970` 傳送到鄰格、面向目標格前進一步（探路用，正式重播不用改記憶體）：

| 值 | 進入後 |
|---|---|
| `20` | 走廊 |
| `22` | 固定遭遇（例如 (8,8) 遇到 Kasuruji），播 `END0.IBM` |
| `26` | 電梯，選單 Leave／Go up |
| `27` | 電梯，選單 Leave／Go down |
| `30` | 寄放盟友（(15,8)） |
| `31` | Bio Room，治療（(9,2)） |
| `32` | Antiques（(9,5)） |
| `33` | Relic Shop（(6,3)） |
| `34` | Repairs（(6,12)） |
| `35` | Transport，發現裝置（(6,15)） |
| `36` | Samar's Landing Pad（(1,15)，抵達平台） |
| `23` | Launch Pad（(15,14)，出發平台）：選單 Exit Port／Sivad／Zellwal／Rusteck／Celtac，選 Sivad 即換站，不需要道具 |
| `01`、`07` 等 | 一般房間（(2,13) Radar Room、(0,14) BBS Room） |

### 3.3 電梯

電梯在同一張地圖裡搬位置，不換地圖檔：(7,0) 的 26 號 Go up → X 變 15；(4,2) 的 27 號 Go down → Y 變 10。
兩次都只開了 `ROOM0.PBL`。

### 3.4 探路掃描的做法

目的是找正式重播要走的路線，掃描本身不進重播。

1. **找事件格**：傳送到目標格的鄰格、面向目標格前進一步，依畫面分群。這樣找到 (15,14) 出發平台與 §3.2 各房間。
2. **找通路**：對每個走廊格的每個方向，把兩組座標改好、朝向設成反方向，按向後轉讓遊戲重算 `0x16976`，再按前進，看 X／Y 有沒有被 `0161:23B1` 寫入。
   只改座標、直接前進的話，`0x16976` 沿用傳送前的值，結果全部無效（第一次掃描 954／960 都判成可走）。
   驗證：(1,8) 東不可走、北與南可走，(1,9)、(1,13)、(1,14) 北可走，與正常遊玩一致。
   每次執行最多連走 5 步，避開第 6 步的遭遇。

### 3.5 Sivad 的探路

- 碰撞座標偏移在 Sivad 是固定的 **X ＋ 3、Y ＋ 5**（正常遊玩往北兩步、往東一步，兩組座標同步變化）。偏移依區域不同，不是全域常數。
- 掃描要從**走廊**上的狀態開始：抵達時玩家在降落平台（房間）裡，房間內向後轉沒有作用，通行旗標不會重算，結果全部無效。
- Sivad 出平台後第 2 步就遭遇（敵人 HP 120），所以每次執行只放 **1 個探針**；5 個一組時第 3 個之後全部被戰鬥擋住。
- 結果：426 個走廊方向中 300 個可走；從降落平台出來的走廊只連到 22 格（走廊共 164 格），其餘要經過電梯或房間。

## 4. 限制與重開條件

- 牆壁格的位元意義未解；探路用傳送加前進，不靠解析牆壁。
- 第 6 步遭遇的計數器位址未找到。0–20000h 的傾印在走 0–5 步之間，等差變化的只有座標與線性 `0x06DC9` 的字組（每步 −320）；把它改成 52,700 或 60,000 後走 1 步都不遭遇，排除。另外：監看變數 21–377 的寫入，走 6 步期間除了位置欄位，只有變數 184（每步先寫 0 再寫 FFFEh）與變數 199（第一步 1 → 0）有變動，沒有逐步遞增的值。
  結論：計數器不在 0–20000h 的等差字組、也不在腳本變數 21–377。重開條件（任一）：傾印範圍擴到 20000h–A0000h（`CODE`／地圖檔的載入區）；或在第 5→6 步之間對 `sub_12766` 記錄 opcode 序列，找出「遭遇」分支前讀的位址（M5 作弊或 F3 地圖需要時才做）。
