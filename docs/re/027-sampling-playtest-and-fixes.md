# 027：抽測試玩與它找出來的缺陷

狀態：試玩紀錄（2026-09-18）。對應 issue #27。做法沿用 `docs/re/022`；使用者定案 2026-09-18：**試玩用抽測**，不必走完全程。

## 1. 抽測怎麼做

從第一次試玩的終點（剛抵達賽瓦德的降落平台）接著玩，抽三段正常玩家會走的路徑：

| 段 | 內容 | 上限 |
|---|---|---|
| A | 存檔與讀檔 | 120 步 |
| B | 在賽瓦德找到治療室或下一個發射台 | 120 步 |
| C | 打一場戰鬥 | 120 步 |

代理只看 `pwstep` 的截圖操作（指令 `tools/playtest-sampling-instructions.md`），紀錄在 `workplace/playtest/play2/record.md`。
數字與問題由主迴圈逐條對截圖與轉譯紀錄核對過。

| 數字 | 值 |
|---|---|
| 總步數 | 238 |
| A 段存檔 | 完成（Esc → 選項 → 存檔 → 輸入檔名，全中文，`save1.dat` 產生） |
| A 段讀檔 | **沒測成**：遊戲內選單沒有讀取進度，只有死亡後的標題選單有，而那個選單會逾時自動選「新遊戲」（3 次都來不及） |
| B 段 | 抵達賽瓦德降落平台 2 次；**沒找到**治療室或下一個發射台（3 級角色打不過賽瓦德的敵人） |
| C 段 | 8 場以上：贏舒洛蘇、波斯波伊 ×2、吉夫托克 ×5（多數敵人投降）；輸歐格斯、卡蘇魯基、弗雷古 |
| 卡住 | 1 次（薩瑪出發區的死巷迷宮，84 步） |
| 重來 | 3 次（都是角色死亡） |
| 使用攻略 | 1 次（卡住達門檻後讀 `docs/re/013`，但文件的座標路線與代理的存檔時機對不上，只用得上原理） |

代理回報 9 條問題，逐條核對後：3 條是缺陷（§2.1–2.3，已修）、4 條是暫態（§2.4、2.5）、1 條是工具相容（§4）、

## 2. 找到的缺陷與修法

五個發現裡三個是缺陷（當場修掉、以同一個狀態檔重現確認），兩個是暫態（判定不修，寫明理由）。

### 2.1 Game Over 的三行只有第一行是中文

- 現象：戰敗畫面上 `What will now become of the Alliance's` 與 `fight against Quila's evil empire?!?` 是英文，
  但兩則在文本檔裡都有譯文（`PW.EXE:cs:0901`、`092B`），轉譯紀錄也沒有任何問題事件。
- 原因：A2／A3 路徑的迴圈頭**也會停在字串結尾的 0**。那一次推進了行追蹤，
  於是記憶體裡**相鄰的下一個字串**（起點 ＝ 上一個位址 ＋1）被當成同一行的延續，整行不建疊字。
- 修法：迴圈頭讀到的位元組是 0 就直接返回，不推進行追蹤（`apps/psychicwar/translator`）。
- 驗證：同一個狀態檔重現，三行都有疊字。
- **同一個坑也在覆蓋率工具**（`tools/text_coverage.py` 的 `merge_strings`）：AL ＝ 0 要當成新字串的開頭，
  否則觸發則數會少算。修正後現有重播的數字不變（55 則、不在文本檔 0）。

### 2.2 存檔確認框露出英文

- 現象：「你要現在存檔嗎？」的中文被移除，露出原版的 `Do you want save now?`，而右邊的檔名面板是中文。
- 原因：原版把檔名面板畫在訊息框**右半**上面。疊字的指紋是整行算的，右半被蓋掉就整行失效；
  另外新疊字與舊疊字只重疊一部分時，舊的也被整筆移除。
- 修法（dosgolem `xlate`，規格 `202-translation-overlay`）：
  - 失效判斷改成**逐格**：每格各記指紋，連續 3 次不同就把**那一格**標成透明，全部透明才移除。
  - `Add` 改成**整個被蓋住才移除**，只重疊一部分時把被蓋到的格子標成透明。
- 驗證：同一個狀態檔重現，訊息框左半是中文、面板是中文，畫面上沒有英文。

### 2.3 面板被選單蓋過之後只剩一半中文

- 現象：從發射台的目的地選單回到迷宮後，面板的「向後轉」只有頭尾兩格是中文，中間是原版的 `TURN`。
- 原因：2.2 的逐格遮蓋對訊息框是對的，對**圖檔疊字**是錯的——選單畫在面板上面，被蓋到的格子標成透明之後
  就永遠留在那裡，即使面板重畫也不會恢復（那一筆還活著，watcher 不會重新比對）。
- 修法（dosgolem `xlate`，規格 `203` §2.1）：**watcher 加的疊字整筆失效**，不逐格遮。
  它的有效性由整塊區域定義；移除之後畫面回到原樣時 watcher 會重新蓋。
- 驗證：從 `07-first-play` 開 Esc 選單（蓋住面板）再關掉，六塊面板疊字全部恢復、沒有殘留的透明格。
- ⚠ 舊的疊字層快照裡如果已經有被遮的格子，讀回來還是會帶著；要從沒有被遮過的狀態重跑才看得到修正。

### 2.4 發射台提示同時有中英文（暫態）

- 現象：截圖上同時看到中文「你現在在薩瑪太空站。」與英文 `Our destination`。
- 判定：**訊息框捲動中的暫態**。新的一行印出來之後、捲動還沒結束之前，那一筆疊字被凍結（`docs/spec/009` §4.6）
  而停在「待定色」，不會畫；捲動一結束就變中文。再跑 0.8 秒後確認四筆都是「顯示中」、畫面全中文。
- 不修：凍結是為了避免拿「搬到一半的畫面」定色；代價是捲動那幾幀新行還是原版英文。

### 2.5 戰敗轉場有一瞬間退回英文

- 現象：戰敗轉場的那一兩幀，敵人名稱、狀態欄標籤的中文消失。
- 判定：**原版在轉場時重畫整個畫面**，疊字依規則失效是正確行為；下一個畫面畫完就會重新蓋上。
  屬於可接受的暫態，不修。

### 2.6 讀檔入口很難按到（原版行為，記在這裡給 F10／F11 當理由）

遊戲內的「選項」子選單只有存檔；讀取進度只在**死亡後的標題選單**出現，而那個選單會逾時自動選「新遊戲」，
代理三次都來不及按。這不是翻譯問題，但說明了 F10／F11 即時存讀檔（`docs/spec/012`）對這款遊戲的價值。

### 2.7 代理讀錯的一條

代理記了「敵人投降訊息 `Turnard Here!` 是英文」。放大截圖看，那一行其實是撞牆訊息的第二行
`forward here.`，上緣被訊息框切掉，`f` 看起來像 `T`。同一幀的投降訊息本身有中文疊字（轉譯紀錄有 `4AFB` 的 stamp），
逐像素驗收的 `surrender` 情境也是差 0。
**規則：捲動中的畫面不要拿來判讀文字**；要判讀就等畫面靜止，或看轉譯紀錄。

## 4. 限制

- 抽測只走三段，不是全程；沒走到的路徑仍可能有問題。
- 缺陷 2.1、2.2、2.3 是在試玩**途中**修的，所以 `record.md` 前半的觀察是修之前的狀態，後半是修之後的。
  三個都另外以同一個狀態檔重現驗證過（§2）。
- 途中換疊字層快照的欄位型別，代理遇到一次 `pwstep` 直接中止
  （`json: cannot unmarshal number into ... misses`）。已加相容處理：讀到舊格式就忽略指紋、下一幀重新定色。
  規則：**會被別人手上的舊檔讀到的格式，改欄位型別時要留一條相容的路**，否則對方看到的是「工具壞了」。
