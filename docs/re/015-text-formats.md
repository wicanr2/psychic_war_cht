## 2. `I_MENU*.BIN`

- 以 16 bytes 為一列。字碼 20h–7Eh 是 ASCII；80h 以上是 `FONT.BIN` 的自訂字模（地名等）。
- **訊息**：32 bytes ＝ 31 字元（兩行 16＋15，印字時一行 16 字元，`docs/re/014`）＋ 1 byte 類型碼。
  出現過的類型碼：`0`（279 筆）、`P`（109）、`p`（36）、空白（3）。類型碼的意義未讀（推定與換頁、等待按鍵有關）。
- **選單**：32 bytes 提問，類型碼 `q`、`Q`、`1`、`2`、`3`；之後每個選項 16 bytes ＝ 6 bytes 條件區 ＋ 10 字元標籤：
  - 條件區常見「2 bytes 條件 ＋ 4 bytes 0」（例 `21 01`＝有 Kayla 功能才出現），也見過兩組條件（`32 02 9A 01`），第一個選單的 4 bytes 是空白；
  - 標籤中間出現 00 時截斷（`I_MENU00` 的 Cancel）；
  - 以「00 00 00 ＋ 13 個空白」或只有空白與 00 的列結束。
- `I_MENUH` 是全遊戲共用（Esc 選單、存檔、撞牆等），`I_MENUnn` 是第 nn 區域專屬（`docs/re/011` 的區域編號）。
- 每個檔案的數量：

## 3. `I_ENMY*.BIN`

80 bytes 一筆（400 bytes ＝ 5 筆）：偏移 0 是 2 bytes（推定類型），偏移 2 起 10 字元名字，偏移 0Ch 是敵人 HP（字組）：Kasuruji 70、Shulosu 38、Minton 42，與實戰時 `0x509C` 寫入的初值相同（`docs/re/013`）；其餘數值未解。

## 4. `CODE*.BIN`（腳本）

- 位元組碼，由 `sub_12766` 直譯（`docs/re/011`）。`CODEH.BIN` 開頭是一張 `70 xx xx` 形式的表（推定跳躍表）。
- **內嵌字串**：指令 81h 後接字串到 00 為止，字串內可夾 10h–1Fh 的顏色控制碼（`17 19`、`17 18`），前面常見 `93` 加兩個 byte（推定設定游標）。
  例：`CODE11` 的結局說明、`CODE2` 的「It is a trap !!」、`CODEH` 的方位名稱與道具名。
- 等級：**推定**。依據是三處樣本的位元組形狀；以實跑印字追蹤核對見 §5。

## 5. 以實跑核對

- **I_MENU**：重播 18 段實跑時 `sub_16799` 印出的不重複行共 41 行，**41 行都能在抽取結果找到**（不一致 0）。
  其中一行含自訂字模（`{95}{A5}{B5}{C5}{D5}{96}{A6}` ＝ 畫面上的「Landing Pad」），在 `I_MENU01` 偏移 4F0h。
  比對要用子字串搜尋：`{XX}` 在文字表示裡佔 4 個字元，依字元位置切行會把含自訂字模的行切錯。
- **畫面抽樣**：`13-healed`（Get healed／Leave、I'll give you three Yontry! Come again!）、`16-sivad`（This is Sivad's Landing Pad.）、
  `17-saved2`（Do you want to keep playing? Absolutely）、Launch Pad（Exit Port／Sivad／Zellwal／Rusteck／Celtac）的截圖文字與抽取結果一致，12 則、不一致 0。
- **CODE 內嵌字串**：方位名稱 North／East／South 由 `sub_167B2` 印出，且在 `code.json`（`CODEH`）。
  實跑的投降訊息 `{18}{15}I..I Surrender!{17}` 由 `sub_167BF`（`cs:[BX]`）印出，字串在 `PW_UNP.EXE` 內，不屬於 CODE 檔。
  81h 規則在這次重播路線上沒有反例，但實跑只涵蓋到方位名稱，維持**推定**。

## 6. 限制

- 訊息類型碼、選單條件區的意義未解。
- `PW.EXE` 內嵌字串（防拷畫面、輸入名字）未列入本工具；這些字不經過三支字串函式（`docs/re/014` §4），來源由第 5 輪追蹤。
- 圖檔內嵌文字（`.PBL`）屬 #18，不在本文件。
