# 022：模擬玩家試玩（逐步操作）

狀態：試玩紀錄（2026-09-17）。對應 R6 第 5 項、issue #27。dosgolem 規格 `201-step-actions`；本 repo `cmd/pwstep`、`tools/playstep.sh`。

## 1. 結論

| 數字 | 值 |
|---|---:|
| 總步數（一步 ＝ 一次 `tools/playstep.sh`，看一張截圖） | 84 |
| 目標 1：開機 → 防拷 → 主選單 → 輸入名字 | 第 13 步 |
| 目標 2：打贏第一場戰鬥（Shulosu／舒洛蘇） | 第 27–28 步 |
| 目標 3：找到發射台、選目的地、看到抵達畫面（賽瓦德） | 第 82–84 步 |
| 重來（讀之前的步數） | 0 |
| 卡住（同一件事 10 步以上沒進展） | 1 次，約 50 步 |
| 使用攻略 | 否 |
| 轉譯紀錄的問題事件（缺譯文、過長、缺字、不支援的控制碼、未知呼叫端） | 0 |
| 看到的問題 | 6 條：圖片文字 2、排版 1、翻譯 2、其他 1 |

三個目標都以「看截圖 → 決定按鍵」完成，沒有讀路線文件、沒有改記憶體。

## 2. 做法

- 代理：一個 Sonnet 子代理扮演第一次玩的玩家，指令在 `tools/playtest-instructions.md`（試玩時複製到 `workplace/playtest/INSTRUCTIONS.md`）。
  - 事先知道的只有說明書與畫面等級的資訊：面板上的方向鍵與 Esc、空白鍵攻擊、治療室。
  - 不給說明書的防拷答案。
  - 不准看 `docs/`、`replay/`、`text/`、原始碼。
  - 同一問題卡住 60 步才准讀 `docs/re/013` 當攻略。
- 每一步：`tools/playstep.sh play1 next "<動作>"`。
  - 從上一步的狀態檔推進機器時間，每 1/60 秒做一次疊字定色。
  - 存 `NNN.state`＋疊字層、`NNN.png`（960×600 中文截圖）、`NNN.text.jsonl`。
  - 單步約 2 秒。
- 紀錄：代理每 10 步更新 `workplace/playtest/play1/record.md`（含原版畫面截圖，不進版控）。本文件的問題與結論都經主迴圈對照轉譯紀錄、文本檔、截圖核對過。

## 3. 路線摘要

| 步 | 經過 |
|---|---|
| 001–009 | 開機動畫 → 配對說明 → 防拷題目。沒有說明書，直接按 Enter，**空白答案通過**（「獲准通過」），與 CLAUDE.md 記載的原版行為相同 |
| 010–013 | 標題畫面 → 遊戲選單「新遊戲」→「請輸入你的名字：」輸入 PLAY1 |
| 014–021 | 迷宮裡試前進、轉向、撞牆（「這裡無法前進。」），確認操作 |
| 022–028 | 遭遇舒洛蘇，按住空白鍵連續攻擊獲勝（敵 38 → 0，我方 40 → 18） |
| 029–031 | 走到「這是薩瑪的降落平台。」 |
| 032–081 | 在降落平台找目的地選單：試遍 Esc 選單（問凱拉、看道具、超能力、選項），往西找到佈告欄室，往東途中遭遇敏頓並打贏 |
| 082–084 | 抵達「發射台」，選單列出離開／賽瓦德／濟爾沃／魯斯德克／塞爾塔克，選賽瓦德 →「這是賽瓦德的降落平台。」 |

## 4. 問題與處理

| # | 步 | 類型 | 問題 | 核對結果 | 處理 |
|---|---|---|---|---|---|
| 1 | 010– | 圖片文字 | 操作面板 `ADVANCE`、`LOOK ASIDE`、`TURN`、`ESC OPERATION` 是英文 | 轉譯紀錄沒有對應呼叫，畫在圖檔上 | #18、#25 |
| 2 | 014– | 圖片文字 | 狀態欄標籤 `PLACE`、`DIRECTION` 是英文（值是中文） | 同上 | #18、#25 |
| 3 | 032、044 | 排版 | 句尾問號偏小、偏低 | 「？」是 Noto 補字，點陣化從 y＝0 起畫，下緣被裁掉；24 點的英文字母、16 點的句點同樣被裁 | 已修：補字垂直置中＋空白字模檢查（`docs/re/021` §3.6）；同一狀態重跑第 032 步確認問號完整，逐像素驗收重跑差 0 |
| 4 | 045 | 翻譯 | 問「你要開音效嗎？」，答「好，音樂關掉了。」 | 原文就是 `Sound` 與 `Tunes are off` | 已修：選項、提問統一為「音樂」 |
| 5 | 050 | 翻譯 | 地名「BBS室」中英夾雜 | 自訂字模判讀是 `BBS Room` | 已修：「佈告欄室」（3 則） |
| 6 | 031／082 | 翻譯（可玩性） | 「降落平台」與「發射台」相近，玩家以為降落平台就能選目的地，繞了約 50 步 | 原文是 `Landing Pad` 與 `Launch Pad`，譯名忠於原文；英文版玩家也要分辨這兩個地方 | 不改譯名。F1 說明頁（#29）寫明「發射台才能選目的地」 |

核對時另外確認的一點：「問凱拉」子選單只有「取消」，畫面上沒有漏蓋的英文，轉譯紀錄也只印了「取消」一個選項（原版沒有畫其他選項）。推定原因是 `Mapper`、`Sensor`、`Decoder` 的 6 bytes 條件（`docs/spec/007`）沒有成立，條件判定沒有讀（假說）。

## 5. 限制

- 只走到第一次離站。存讀檔、其他區域、結局都沒試（#27 剩下的部分）。
- 代理看的是 `pwstep` 截圖（機器時間），不是前端的牆上時間；前端的可玩性（按鍵手感、轉場時間）以 `docs/re/016`、`docs/re/019` §5 為準。
- 防拷用空白答案通過，是原版行為，沒有驗證正確答案的判定（#28）。
- 一個代理、一條路線，不代表所有玩家的路徑；「卡住 1 次」只說明這個譯名組合可能造成混淆。

## 6. 重現

```
tools/go-ebiten.sh build -o /src/workplace/bin/pwstep ./cmd/pwstep
# 依 tools/playtest-instructions.md 逐步執行：
tools/playstep.sh play1 new "wait:12000"
tools/playstep.sh play1 next "tap:Space,wait:4000"
```
