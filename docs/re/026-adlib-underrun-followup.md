# 026：AdLib 路徑的 60 秒欠載（追量）

狀態：量測紀錄（2026-09-18）。對應 issue #13（即時音訊輸出）、#5（OPL2）。承接 `docs/re/016` §2.4、`docs/re/019` §6。

## 1. 結論

| 數字 | 值 |
|---|---:|
| 牆上時間 | 65 秒 |
| 欠載總數 | 102 |
| 其中開場第 1 秒 | 34 |
| 第 2–50 秒 | **0** |
| 第 51–54 秒 | 68（同一時間主機 load average 由 5.95 升到 16.44） |
| 第 55–65 秒 | 0 |
| 放棄追趕 | 677 ms（其中 153 ms 在第 1 秒） |
| CPU 佔用 | 1.80 核 |

**AdLib 路徑可以連續 50 秒不斷音**（第 2–50 秒欠載 0）。第 51–54 秒的欠載與主機負載尖峰同時發生，
不是前端本身的問題——但**這一點不能只用相關性斷定**，要在空閒主機重量才算乾淨數字。
第 1 秒的 34 次與 `docs/re/016` §2.2 記的開場（第一次繪圖編譯 shader）一致。

## 2. 為什麼這次量得出東西

`docs/re/019` §6 記的重開條件是「load average 連續 5 分鐘 < 2」。這次開跑時 load 5.95（14 核），
不符合那個條件，但**負載下的「通過」仍然是證據，負載下的「不通過」才不是**：
CPU 被搶只會讓欠載變多，不會讓它變少。所以「連續 50 秒 0 次」這個數字成立；
第 51–54 秒那一段則不下結論。

規則：**在不理想的條件下量，先想清楚這個條件會讓結果偏哪一邊**。偏向「更難通過」時，通過就算數。

## 6. 真實裝置上的數字（2026-09-18，使用者授權「接聲音」）

**兩條路徑都通過**（`docs/spec/020`，`tools/audio-device-check.sh`）：

| | AdLib | PC 喇叭 |
|---|---:|---:|
| 牆上時間 | 65 秒 | 65 秒 |
| 欠載總數 | **6** | **6** |
| 其中開場第 1 秒 | 6 | 6 |
| **第 2 秒之後** | **0** | **0** |
| 放棄追趕 | 142 ms | 139 ms |
| 溢位 | 434 | 800 |
| CPU 佔用 | 1.88 核 | 1.87 核 |
| 機器時間／牆上時間 | 0.9978 | 0.9978 |
| load average（14 核，開跑 → 結束） | 6.94 → 7.03 | 6.62 → 3.15 |

接法：掛主機 PipeWire 的 pulse socket，容器內 ALSA 走 pulse plugin，**不獨佔音效卡**。
反向對照（`docs/spec/020` §4 第 4 項）也過：機器時間／牆上時間 0.9978 落在 1 ± 0.01 之內，
所以「欠載 0」不是因為它跑得慢、產得少。

與 `-audio null` 的數字（§5：欠載 37 次全在第 1 秒）比：**真實裝置上的第 1 秒欠載反而更少**（6 次）。
兩者的第 1 秒都是繪圖初始化那一段，差異在緩衝的填法，不影響結論。
溢位（434／800）是 null 路徑沒有的——那是裝置端消耗得比我們產得慢時的正常現象。

### 6.1 走過的兩條死路



| 路 | 結果 |
|---|---|
| 直接掛 `/dev/snd` 開 `hw:0` | `oto: ALSA error at snd_pcm_hw_params: Invalid argument`——主機的 PipeWire 管著那張卡，開不起來 |
| ALSA 的 `null` PCM | 跑得起來（`libasound` 內建，不必裝套件、不必音效卡），但**數字沒有意義**：65 秒欠載 290,203 次 |

**`null` PCM 不是 dummy sink**：它不按取樣率消耗資料，而是**立刻吸收**送進去的一切。
應用端於是一直被要資料，緩衝永遠是空的，統計就把每一次都算成欠載——
第 2 秒之後每秒穩定 3,000–4,000 次，形狀一看就不是真實的欠載（真實欠載是偶發的尖峰）。
CPU 1.94 核（`-audio null` 是 1.87），確實多做了事，只是做的不是我們要量的那件事。

規則：**dummy sink 要會按時序消耗，否則量到的是它自己的行為，不是待測系統的**。
可行的替代是 `snd-dummy` 核心模組或 PulseAudio 的 null sink——兩者都要動到容器之外的東西，
留給有音效卡的機器。

`-audio null` 路徑的數字（§5）仍然成立：那條路徑不開裝置，量的是**前端的合成與節拍跟不跟得上**，
與裝置無關的部分。裝置緩衝那一段由 §6 補上。
