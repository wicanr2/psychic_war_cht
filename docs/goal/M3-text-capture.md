# M3：文字攔截與文本抽取

## 目標

**知道遊戲裡每一則文字從哪來、在哪裡畫，而且全部抽成可以翻譯的文本檔。**
這是 ScummVM 模式能不能成立的關鍵：文本抽得乾淨，翻譯就是填表；抽不乾淨，就會退回逐畫面修補。

## 完成定義

| 項目 | 驗收 | issue |
|---|---|---|
| 印字常式 | 字元層與訊息層常式的位址、參數（字串指標、座標、顏色、寬度）、呼叫點進 `docs/re/`；`FONT.BIN` 格式確認 | #15 |
| 文字格式 | `I_MENU*`、`I_ENMY*`、`CODE*`、`PW.EXE` 字串表的格式規格標 READY，附位元組簽章；`CODE0–10.BIN` 有結論 | #16 |
| 抽取工具 | 從玩家自備的原版產生 `text/`；每則含來源（檔名＋偏移）、原文、欄寬、譯文；缺原版時明確報錯 | #17 |
| 圖檔文字 | `.PBL` 格式規格 READY；含文字的圖清冊（檔名、座標、原文） | #18 |
| 覆蓋率量測 | 對任一重播檔輸出：抽出幾則、翻了幾則、實跑觸發幾則、觸發了卻不在文本檔的幾則 | #19 |

## 量測指標

- 文本檔筆數與格式規格的預期一致。
- **「觸發了卻不在文本檔」：0**（以 M1 #8 的全程重播量測）。

## 設計約束

- 替換單位是**一則訊息**，文本檔的 key 是來源位置，不是畫面上的字串。
- 文本檔的原文欄位屬於原版素材：要能由工具從玩家檔案重新產生；在做到之前，含原文的文本檔不進公開 repo。
