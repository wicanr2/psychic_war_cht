# 第 4 輪：可遊玩前端雛形、找出印字常式

## 目標

**讓人第一次能在視窗裡以 AT 8 MHz 的速度玩原版，同時找到遊戲畫字的入口。**
前端雛形回答「golem 當執行器給人玩」是否成立（M2）；印字常式與文字格式是中文化的起點（M3）。

使用者定案沿用：**dosgolem 的修改在整個遊戲移植完成後一次發 PR**；本輪繼續疊在本機分支上。

| 重播檔 18 段：開機 → 4 場戰鬥 → 兩次存讀檔 → 抵達 Sivad | `replay/title-to-first-save.json`、`docs/re/013`、`tools/states.sh --check` |

## 本輪完成條件

以下全部成立才算完成：

1. **前端雛形（#9、#10、#11、#13）**
   - 規格 READY：前端框架（預設 Go／Ebiten）、目錄位置、與 dosgolem 的介面（每幀跑多少 cycles、畫面與聲音怎麼取）、支援平台。
   - `cmd/psychicwar`（或規格定的位置）開視窗，320×200 EGA 畫面 nearest 整數倍放大，顏色與 `tools/states.sh` 的 `.rgb.png` 逐像素相同。
   - 以 750 cycles 對齊牆上時間：量 60 秒實跑，機器時間與牆上時間差 ≤ 1%；計時器中斷 72 Hz ±1%；CPU 用量有數字。
   - 鍵盤：前進、轉向、空白鍵**按住**、Esc 選單、輸入名字可用；F1／F2／F3／F10 被前端攔下不送進遊戲。
   - 音訊：PC 喇叭與 AdLib 至少一種即時發聲，60 秒沒有斷音（以輸出緩衝欠載次數量）。
   - 驗收方式：以程式送輸入（不是人手），在前端走完重播檔的 01–09 段，打贏第一場戰鬥；另外記錄一次人手操作的結果（可以輸，要有紀錄）。
   - 通用部分（牆上時間對齊、按鍵狀態）送 dosgolem 分支並寫規格；視窗與音訊輸出先放本 repo。
2. **印字常式（#15）**
   - 找出遊戲把文字畫到畫面的常式：位址、參數（字串來源、座標、顏色）、字模來源（`FONT.BIN` 或其他）。證據要有動態監看或改值驗證。
   - 寫進 `docs/re/`，列出攔截點候選與各自的限制。
3. **文字資料格式（#16）**
   - `I_MENUnn.BIN`、`I_ENMYnn.BIN`、`CODEH／CODEn.BIN` 至少各解一種結構到「能列出所有字串與偏移」；腳本直譯器用到的字串引用方式寫清楚。
   - 抽取工具的雛形（本 repo，docker），對 `I_MENU00.BIN` 產出字串清單；以重播檔實跑時畫面出現的文字抽樣核對，列出核對筆數與不一致數。
4. **收尾第 3 輪留下的開放項（各給結論或重開條件）**
   - `docs/re/010` §4.2 的 4 組分岔原因（至少排除或證實「按鍵重複的步數不同」這一條）。
   - 遭遇步數計數器的位址。
   - Sivad 的碰撞座標偏移（探路掃描可在 Sivad 用）。
5. `tools/py.sh tools/worklist.py verify` 沒有「可能已完成」；做完的條目移到 `done`；本機 commit。

## 量測指標

- 前端：牆上時間誤差 %、72 Hz 誤差 %、CPU 用量、音訊欠載次數、程式輸入走完 01–09 段是否打贏。
- 印字常式：攔截到的字串數、與畫面核對的筆數。
- 文字格式：每種檔案解出的字串數；抽樣核對的一致率。

## 工作邊界

- SDD：改 dosgolem 前先寫規格標 READY；本 repo 的格式與方法寫 `docs/spec/`。每次改 dosgolem 跑全套測試；碰到顯示相關修改另跑 eob1 回歸（`docs/re/009` §6 的做法）。
- 全部走 docker（含前端建置；視窗實跑用 Xvfb 截圖驗證）；只清理自己建立的 container，禁止 prune／`rmi`。
- 原版與說明書掃描只在 `workplace/`；文件只摘要說明書，不轉錄；文字抽取的產物不進版控（原版文字屬原作）。
- **push、PR 先問**；issue 狀態與留言可以直接更新（使用者 2026-09-17 授權）。
- 防拷略過屬 M5，不在本輪。
