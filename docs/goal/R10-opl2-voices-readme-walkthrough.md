## 本輪完成條件

1. **OPL2 逐聲道比對（#5）**
   - 整曲是 9 個聲道的混音，**單一聲道錯了會被其他聲道稀釋**——這是目前最缺的解析度。
     合成器加「只渲染第 N 聲道」的選項（診斷用，與 `-opl-disable` 同一類）。
   - 找出 15 秒之後是哪幾個聲道不像；那一段的參數特徵已經知道（回授從清一色 7 變成以 5 為主、
     慢起音 AR ＝ 9 大增），對照著看。
   - 驗收：`docs/spec/016` 的三個指標，全曲前 30 秒都要過門檻。過不了就寫明差在哪一個聲道、哪個參數。
2. **README（#37）**
   - 遊戲介紹、中文截圖、怎麼玩、熱鍵表、進度、授權與字型來源（含下架聯絡方式）。
   - **先決定**：截圖裡有原版美術，README 放截圖算不算散布原版素材（本 repo 的 `[HARD]` 規則）。
     這件事要先問過再動手。
   - 依 `rulebook/80`（retro 中文化 README）、`rulebook/90`／`91`（白話、去 AI 味）寫。
3. **當年攻略整理（#38）**
   - 《軟體世界》19 期 29–38 頁，10 頁掃描逐頁判讀，整理成 markdown 放 `docs/`。
   - **掃描圖不進 repo**（原版素材）；內容改寫不逐字轉錄，標明出處。
   - 同時當譯名的校對材料：攻略裡的人名、地名、超能力名稱與 `text/glossary.json` 對齊，
     不一致的列出來處理。
4. **即時音訊（#13）**
   - 真實音效卡或 dummy sink 上量 60 秒欠載（null 輸出已經是第 2–65 秒 0）。
   - ⚠ **這台機器做不到**（`docs/re/026` §6）：容器沒有 `/dev/snd`；ALSA 的 `null` PCM
     不按時序消耗資料、立刻吸收，量到的 29 萬次欠載是它自己的行為。
     要 `snd-dummy` 核心模組或 PulseAudio 的 null sink——**換一台有音效卡的機器再做**，
     或先確認可以在這台載入 `snd-dummy`。不要再花時間在容器內找替代品。
   - 量測條件：每核負載 < 0.5（這台 14 核 ＝ load < 7）。
5. `tools/py.sh tools/worklist.py verify` 沒有「可能已完成」；做完的條目移到 `done`；本機 commit。
