## 本輪完成條件

1. **疊字的挖空模式（dosgolem，#25 收尾）**
   - 規格先寫 READY（`202-translation-overlay` 新增）：**只畫字的像素，其餘保留原畫面**。
     目前只有「把格子填成背景色再畫字」一種畫法，遇到雜訊底就把底紋抹平。
   - `OPEN.PBL` #7–#9 的字幕條用這個模式疊上中文（那三張的字是從紅色雜訊底挖空的）。
   - 驗收：逐像素差 0（期望值 ＝ 原版那塊 ＋ 只換字的像素）；反向對照；底紋像素一個都不能動。
   - 做完之後圖檔文字 48／50 張，剩下的兩張是定案保留的標題美術字，`#25` 可以關。
2. **OPL2 合成（#5）**
   - 先定「怎麼算通過」：`docs/re/007` 的方法（`tools/music_compare.py opl`）分辨力不足，
     做完也無法宣稱成功。判準定不下來就寫明改用什麼（例如與 DOSBox-X 的 `.dro` 逐事件已經相同，
     那麼要驗的是合成器本身，可以拿單一音色的已知波形對）。
   - 驗收：標題曲與迷宮曲各一段，與 DOSBox-X 錄音的音高、節奏比對通過。
3. **即時音訊輸出（#13）**
   - 目前只在無音效卡的 null 輸出驗過。要在有音效卡（或 dummy sink）的情況下量欠載。
   - 驗收：60 秒 AdLib 欠載 0（開場第 1 秒除外）；PC 喇叭同樣。**量測條件**：每核負載 < 0.5
     （這台 14 核，等於 load < 7）。第 8 輪的 `-audio null` 路徑在每核 0.36 時量到
     第 2–65 秒欠載 0，所以這個門檻是夠的——原本寫的「load < 2」是為 4 核機器寫的絕對值。
4. **輸入名字（#26）**
   - 原版只收 ASCII，存檔檔名是 `<名>.DAT`。中文名字要嘛只在顯示層轉換（存檔仍用 ASCII 代號），
     要嘛限制玩家輸入 ASCII 但把提示文字中文化。**兩條路的代價不同，規格先寫再實作。**
   - 驗收：輸入、存檔、讀檔、狀態頁顯示四處一致；存檔檔名在 DOS 檔案系統上合法。
5. **開放項的收尾**
   - #9：5 場有效樣本已經取得（平均 19.70 秒，比 dosgolem 高 10.4%，`docs/re/010` §4.6），
     但那是**上界**——兩場在 load 5–10 下跑，DOSBox-X 只會更慢。
     要下「差 ≤ 10%」的定論，在每核負載 < 0.3 時補 3 場。
   - AdLib 的 `-audio null` 路徑已經是第 2–65 秒欠載 0（`docs/re/026` §5）；
     缺的是**真實音效卡（或 dummy sink）**上的數字，與第 3 項同一次量測。
6. `tools/py.sh tools/worklist.py verify` 沒有「可能已完成」；做完的條目移到 `done`；本機 commit。

## 量測指標
