# 第 5 輪：文字攔截收齊、畫出第一句中文

## 目標

**把「遊戲印出的每一個字從哪來」量到可以對帳，並在前端畫出第一句中文。**
第 4 輪找到印字常式與 `I_MENU` 格式，但三支字串函式只涵蓋實跑約 25% 的字元；本輪補齊其餘路徑、把文本檔落地，
再用少量譯文驗證「攔截 → 換字 → 疊在放大畫布上」這條路走得通（M3 收尾、M4 起步）。

使用者定案沿用：**dosgolem 的修改在整個遊戲移植完成後一次發 PR**；本輪繼續疊在本機分支上。

## 量測指標

- 印字：單字元層字元總數、已歸來源數、歸不到來源數（目標 0）。
- 文本：每種檔案的則數；規格預期數與實際抽出數的差。
- 覆蓋率：四個數字。
- 中文繪製：中文字區域不同像素數；缺譯紀錄數。

## 工作邊界

- SDD：改 dosgolem 前先寫規格標 READY；本 repo 的格式與方法寫 `docs/spec/`。每次改 dosgolem 跑全套測試。
- 全部走 docker（含前端建置與 Xvfb 驗證）；只清理自己建立的 container，禁止 prune／`rmi`。
- 原版文字只在 `workplace/` 與 private repo 的 `text/`；文件只摘要說明書，不轉錄。
- 譯名優先沿用軟體世界說明書；本輪只翻驗證用的幾則，不做全文翻譯（M4 #24）。
- **push、PR 先問**；issue 狀態與留言可以直接更新。
- 字型：只烘製驗證用字的子集；字型來源與授權寫進 spec（`rulebook/81`）。
